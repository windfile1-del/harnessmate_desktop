# B2-W3 Harness 集成

基线为 `6099b2c1290f70011eeb64fb2244670bfb3790e2`。交付分支为 `codex/b2-w3-harness`。在该分支运行 `git rev-parse HEAD` 获得报告对应的提交。

## 装配与调用

| 插件身份 | 默认实例 | 契约 | 作用域 |
| --- | --- | --- | --- |
| `core.account-usage` | `usage` | `harness.usage.v1`、`harness.model-catalog.v1` | 组合或会话绑定选择插件实例，驱动实例区分账号 |
| `core.auto-failover` | `core.auto-failover` | `session.failover.v1` | 组合、工作区或会话绑定，策略按插件实例持久化 |
| `core.mcp-hub` | `core.mcp-hub` | `harness.mcp-config.v1` | 绑定选择管理实例，CLI 配置路径区分账号并协调写入 |
| `core.session-model-tools` | `core.session-model-tools` | `session.model-tools.v1` | 会话绑定、插件运行代次和驱动句柄 |

默认组合启用以上实例。用量和 MCP 管理的原模态入口解析当前服务绑定。预装包和替代包均声明 `workspace.pages` 的 `account-usage` 或 `mcp-config` 槽位，由同一入口加载所选实例的包内 HTML 页面。页面桥按持有的实例调用该实例的路由。2026-11-27 已删除宿主专用 React 页面，返修与成品复验记录见[返修报告](fixes-2026-11-27.md)。

| 旧入口或新消费点 | 方法与语义 |
| --- | --- |
| `GET /api/v1/usage/accounts` | `harness.usage.v1.listAccounts({ forceRefresh })`。保留 `accounts`、`collectedAt`、原驱动和账号回执，支持可选 `sessionId` |
| `/usage` | 按会话选择额度实例。AGY 使用原 Profile 下的 CLI 用量命令，Claude 原生命令仍由现有执行链处理 |
| `GET /api/v1/sessions/:id/model-candidates` | `harness.model-catalog.v1.listModels({ sessionId, harnessInstanceId, refresh? })`。返回现有模型 DTO、驱动状态、默认模型、驱动实例 ID 和服务解析结果。会话的已选模型继续由现有驱动回执确定 |
| `GET/PUT /api/v1/usage/failover-policy` | `session.failover.v1.getPolicy/setPolicy`。兼容原策略 DTO，支持可选 `sessionId` |
| `GET /api/v1/sessions/:id/failover-recommendation` | `session.failover.v1.recommend({ sessionId, failedInstanceId, failureClass })`。保留排序后的候选、冷却和可用状态、自动接力判定及降级原因 |
| `POST /api/v1/sessions/:id/failover` | 会话管理器执行切换和原失败轮次重放。策略实例只读取重放所需输入并给出建议。策略关闭后仍可手动切换 |
| `GET/POST /api/v1/mcp/servers`、`PATCH /api/v1/mcp/servers/toggle`、`DELETE /api/v1/mcp/servers/:harnessId/:name` | `harness.mcp-config.v1.list/add/toggle/remove`。保留逐目标回执、预设、原 CLI 命令和协议格式。目标既可使用旧的 CLI ID，也可使用真实驱动实例 ID |
| `POST /api/v1/plugin-tools`、会话详情和命令视图 | 所选 `session.model-tools.v1` 提供目录和 lease。保留 MCP JSON-RPC、原审批决策和会话命令链 |

W2 可先用 `GET /api/v1/sessions/:id/model-candidates` 和 `GET /api/v1/sessions/:id/failover-recommendation` 做夹具。前者按会话当前账号返回候选，后者可带 `failedInstanceId` 和 `failureClass` 读取历史失败所在实例的建议。内嵌插件可用已有 `ctx.services.call` 传真实 `sessionId` 解析只读建议和目录。服务停用或绑定失效时，HTTP 适配返回 `409 / E_SERVICE_UNAVAILABLE`。

## 数据与回退

| 资源键 | 旧归属与写入者 | W3 所有者与回退读取 |
| --- | --- | --- |
| 驱动实例 ID、账号配置、用量聚合 | 驱动配置和 SQLite 中的会话运行统计。额度查询读取驱动回执 | 原路径和数据库格式。W3 用量实例维护各自的短期探测缓存，按驱动实例及适配器身份隔离，停用或换代时丢弃迟到结果。旧包继续读取原数据 |
| `global / core.auto-failover / failover_policy` | 默认策略的插件 KV | 默认实例原地读写。新增策略实例用自己的 ID 作为 KV 命名空间。旧包继续读取默认实例写入的配置 |
| 解析后的 CLI 配置路径 | CLI 原生配置由各 CLI 自己写入 | MCP 管理委托原 CLI 子命令。当前进程内按实际配置路径有序执行，跨 CLI 逐项保留结果。旧包和原生 CLI 继续读取相同配置 |
| 会话 ID、驱动适配器、运行代次和 lease | 先前由会话工具代码持有内存态 | 令牌和工具路由归所选实例。停用后撤销该代次 lease。驱动替换、授权变化或绑定变化会使旧令牌失效。令牌无需迁移或导出 |

切换与回退可用组合页停用和重新启用同一实例，再恢复默认组合。保留数据库、默认策略 KV 和 CLI 已完成写入。多 CLI 安装失败时，模态保留输入和失败目标供重试。需要撤销已经完成的安装时，用同一账号的 MCP 移除操作。旧 EXE 回退要使用升级后的独立数据副本。

## 复验命令

在 W3 分支仓库根执行。下列配置把夹具和日志放在工作区内的 D 盘目录。

```powershell
$env:W3_FIXTURE_ROOT = Join-Path (Get-Location) 'data/w3-tmp'
New-Item -ItemType Directory -Force $env:W3_FIXTURE_ROOT | Out-Null
$env:TEMP = $env:W3_FIXTURE_ROOT
$env:TMP = $env:W3_FIXTURE_ROOT
$env:TMPDIR = $env:W3_FIXTURE_ROOT
$env:HARNESSMATE_TEST_TMP = $env:W3_FIXTURE_ROOT
pnpm contracts:check
pnpm build
pnpm typecheck
pnpm --filter @harnessmate/daemon exec vitest run tests/b2-w3-mcp-config.test.ts tests/usage-failover.test.ts tests/plugin-capabilities.test.ts --maxWorkers=1
pnpm --filter @harnessmate/web exec vitest run tests/phase2-v5-studio.test.tsx tests/peer-plugins.test.tsx --maxWorkers=1
node packages/daemon/tests/fixtures/b2-w3-harness-smoke.mjs
git diff --check
```

外部额度替代夹具在 `plugins/examples/hm.plugin.w3-account-usage-fixture`。将其作为本地目录安装，给其签入的 `service:provide:harness.usage.v1` 授权，将会话 B 的用量契约绑定到该实例，再从会话 B 打开用量模态。会话 A 保持使用 `usage`。编译后 daemon 的夹具命令核对服务解析、旧 HTTP 入口、资产和页面路由。
