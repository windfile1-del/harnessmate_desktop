- `GET/PUT /api/v1/sessions/:id/task-state` 调用账本的 `get/update`。旧 GET 会按需建立空账本。会话详情在提供方停用或读取失败时可读取原库快照。旧独立账本路由在实例不可用时返回 404。
- `POST /api/v1/sessions/:id/task-state/summarize` 先选择摘要实例，再调用该会话绑定的账本。旧消息正文、草稿、会话运行、审批和问题卡继续走原入口。
- `GET /api/v1/triage/state`、`PATCH /api/v1/triage/sessions/:id`、`POST /api/v1/triage/sessions/:id/viewed`、`POST /api/v1/triage/check-snoozes` 保留旧字段和 409 停用态。检查响应增加可选 `reminders`，用于启动或重连后通知恢复。原生通知规划通过 `POST /api/v1/desktop/session-notifications/plan`，审批许可仍由原审批 API 写入。
- Studio 从当前会话取得工作组和条目上下文。工具输出请求以会话 ID 和真实条目 ID 读取持久化详情。展开 shell 工具时以会话 ID 和真实工具调用 ID 订阅 CommandOutputHub，收起、结束输出、切换实例或卸载视图时清理订阅。小地图沿用会话和轮次跳转。
- 内核资产包使用现有沙箱页面，第一方处理器在宿主注册。独立开发基线的内核上下文缺少 `ctx.routes.register`，W1 合入后补齐该原语。W2 的账本和收件箱仍通过有界 `surface.action` 调用已选实例的兼容 API，目录安装插件可以使用 `plugin.route`。命令面板和侧栏布局沿用现有入口。
- W1 联动后，账本使用 `git.workspace.v1` 的可选 `getStatus`，停用 Git 实例后沿用已保存的账本。Studio 文件条目调用 `navigateToFile`，传入当前工作区、会话、路径和可选行号。保留流式工具的调用 ID 和持久化条目 ID。默认启用的 Studio 资产不扩大模型 MCP 工具清单，已有 HTML 活动仍可触发旧工具发现逻辑。

## 数据所有权与回退

| 资源键 | B1 位置及写入者 | W2 写入者及提交边界 | 回退读取 |
| --- | --- | --- | --- |
| 任务状态 / 会话 ID | `session_task_state`，旧账本及旧会话适配 | 默认 `ledger` 复用原行。补投影与水位同一 SQLite 事务，失败后重读已提交事件。其他本地账本实例在独立 KV 归属写入 | B1 读取默认实例增量。额外实例数据需另行导出 |
| 任务镜像 / cwd 与会话 ID | `.harnessmate/task-ledger.md`、`.harnessmate/sessions/<id>.md` 及元数据 | 默认账本沿用原路径、已有三方合并和原子文件替换。自动完成轮次在数据库提交后更新镜像。数据库与多个文件不是同一事务 | 原路径和内容格式可读，镜像恢复依赖默认账本启用 |
| 补投影位置 / 账本实例与会话 ID | 无 | 旧主账本按 `core.task-ledger` 归属保存 `projection:<sessionId>`。其他账本实例拥有独立水位。B1 变更流用于发现已提交的会话变化，轮次唤醒后重读 SQLite 中的事件 | B1 忽略新 KV |
| 待办元数据 / 收件箱实例与会话 ID | 全局 KV，`hm.plugin.triage-inbox`，会话 ID 作键 | 默认实例原地复用。其他实例使用各自 KV。投影从会话、审批计数、轮次和已运行任务读取 | B1 可继续读取原键的置顶、已读、已处理、延后状态 |
| 已到期提醒 / 收件箱实例与会话 ID | 无恢复记录 | 到期清空和最新到期提醒在同一事务落盘。原生通知接收方按提醒或审批事件身份记忆收据 | B1 读取原待办状态并忽略恢复记录，已发送系统通知是外部副作用 |

停用、启用和修订回退前保留隔离数据副本。切换实例时保留原作用域绑定，按原数据键核对默认实例；不要把两个实例设置成同一默认账本的数据写入者。回退整个组合时先停 W2 进程，再从相同副本起 B1，旧账本和旧待办 KV 可原地读取。目录安装示例可以在插件中心解除绑定后卸载。

第三批需接手 SQLite 的窄读取适配 `readCommittedLedgerEvents`，以及遗留 Fork、MergeBack、历史导入和交接引用。旧导入路径会携带原始任务快照。镜像文件的多文件事务与额外实例历史格式导出仍需后续处理。

## 复验

在隔离工作区设置 D 盘临时根，可使用以下 PowerShell 命令。安装依赖和 Electron 缓存也应指向 D 盘。

```powershell
$w2RunTemp = 'D:\HarnessMate\b2-tmp\w2'
New-Item -ItemType Directory -Force $w2RunTemp, data/w2-tmp | Out-Null
$env:TEMP = $w2RunTemp
$env:TMP = $env:TEMP
$env:NODE_COMPILE_CACHE = Join-Path $env:TEMP node-cache
pnpm contracts:check
pnpm build
pnpm typecheck
pnpm --filter @harnessmate/daemon exec vitest run tests/b2-w2-session-assistance.test.ts tests/triage-inbox.test.ts tests/handoff-v2.test.ts --maxWorkers=1 --testTimeout=60000 --hookTimeout=60000
pnpm --filter @harnessmate/daemon exec vitest run tests/b2-w1-workspace-tools.test.ts tests/b2-w2-session-assistance.test.ts tests/triage-inbox.test.ts tests/handoff-v2.test.ts tests/plugin-replay.test.ts tests/b1-01-service-resolution.test.ts --maxWorkers=1 --testTimeout=60000 --hookTimeout=60000
pnpm --filter @harnessmate/web exec vitest run tests/b2-w1-workspace-ui.test.tsx tests/phase4-triage-inbox.test.tsx tests/b2-w2-notifications.test.ts tests/phase2-v5-studio.test.tsx --maxWorkers=1
pnpm --filter @harnessmate/electron exec node scripts/stage-bundle.mjs
node scripts/plugin-decoupling-batch-2/w2-replay.mjs data/w2-tmp/replay-recheck D:/HarnessMate/b1-pack/release/win-unpacked/resources/web-dist
node scripts/plugin-decoupling-batch-2/w2-legacy.mjs data/w2-tmp/legacy D:/HarnessMate/b1-acceptance/legacy-readonly-copy D:/HarnessMate/b1-pack/release/win-unpacked/resources/daemon/daemon.cjs
```

1. 开启收件箱，在已有会话编辑账本目标或置顶事实，再打开收件箱查看、置顶并延后该会话。通过收件箱条目返回会话。到期后重启实例，检查 `expired` 与 `reminders`，以事件身份判断是否为同一提醒。
2. 用确定性回放打开运行中的工具，观察工具订阅携带真实调用 ID，检查沙箱里输出更新。收起工具后验证对应取消订阅。在插件中心停用 Studio，继续读正文和输入草稿，再操作账本和收件箱。
3. 从 `plugins/examples/user.session-studio-fixture` 安装目录，给第二个会话绑定 `session.studio.v1`。第一个会话保留预装实例。Git 夹具接受 `{ workspaceId, sessionId, cwd }`，建议夹具返回候选、原因与动作。真实联动用未跟踪的 `work-log.md` 检查 W1 Git DTO 和 W2 账本，用 `工作记录.md` 检查第 2 行的文件跳转。
4. 关闭默认账本、提交一个轮次，再启用账本。在写入投影水位时注入异常，数据库中账本和水位同时回到旧值。取消故障并重启，确认轮次补齐一次，手动目标和钉选仍在。专项用例自动执行这些断言。
5. 旧包回退使用脚本输出的 `run` 数据副本。将 `HARNESSMATE_DATA_DIR` 指向该副本，将 `HARNESSMATE_PORT` 和副本 `config.json` 的 `port` 设为同一未占用回环端口，关闭 `lanEnabled`。将 `APPDATA`、`LOCALAPPDATA`、`TEMP`、`TMP` 和 `--user-data-dir` 指到 D 盘隔离目录，再启动 B1 便携 EXE。用旧 API 查询账本目标 `W2 isolated legacy rollback probe`、同会话 `pinned` 和 `forceUnread`。

## 候选交接

共用文件保留 W1 的 Git、检查点、终端及文件入口，W2 的账本和通知适配单独装配。候选用 `git rev-parse codex/b2-integration` 取得，供 W3 以合并候选为基线接线。合并后的 W2 证据及临时目录都位于 D 盘。W3 负责最终 Windows 候选打包和原生通知弹出的桌面验收。

W1 的 Git 状态在默认 `core.quotePath` 下可能将中文 Git 路径以转义形式返回。联动用例分别验证了实际 Git 状态投影与中文侧栏导航。最终候选回归需继续关注 W1 状态 DTO 中路径的呈现。
