### 2.2 实例身份模型

全链路明确区分以下六个维度（见 `packages/plugin-api/src/driver-contracts.ts` 与 `packages/daemon/src/harnesses/types.ts`）：

1. **`pluginId`**：插件包标识符（如 `core.harness.codex` 或第三方 `hm.plugin.codex-driver-lite`）。
2. **`instanceId`**：同一插件包安装/配置的具体实例 ID（如 `codex`、`codex-work`、`claude-personal`），驱动目录与工作区绑定均按实例区分。
3. **`harnessId` / 账号上下文**：会话使用的逻辑驱动实例键，同包多实例支持独立的 CLI 路径、Home/Config 目录（`CODEX_HOME`、`CLAUDE_CONFIG_DIR`）、环境变量白名单过滤（`sanitizeInstanceEnv(envWhitelist)`）与账号状态。
4. **`driverId`**：驱动协议类别（`codex` / `claude` / `acp` / `agy`），已移除第三方不得注册 `codex` / `claude` / `acp` 的硬编码限制；仅 `agy` 保留至第四批。
5. **`runId` (`providerRunId`)**：插件进程/激活代次标识，在途 `AdapterSessionHandle` 绑定 `providerPluginId`、`providerInstanceId`、`providerRunId`。
6. **`nativeSessionId` & `continuationKey`**：底层 CLI 原生会话线程 ID 与跨实例续接键。

### 2.3 旧 ID 与配置迁移映射

- **`binaryOverrides`（`codex` / `claude` / `agy`）**：自动映射到对应默认实例或覆盖实例的 CLI 可执行文件路径，无需用户手工重写既有配置。
- **`harnessInstances`（多实例配置）**：每条实例独立进入默认插件实例化配置（`codex` / `claude` 实例各自注册对应 `driverId` 与 `harnessId`），可同时并存并在 `/api/v1/harnesses?workspaceId=...` 与标准会话入口选择。
- **`customAcpHarnesses`**：映射到 `core.harness.acp` 插件实例托管与 `/api/v1/harnesses/custom*` 兼容路由；`core.harness.acp` 停用后不再由宿主兜底创建。
- **`agyProfiles`**：继续由 `core.harness.agy` 注册至 `HarnessRegistry.registerProviderDriver(...)`，保留原 profile `harnessId`、native 路由、审批策略及溯源校验。
- **`harnessmate-core.json` `stableIds` & 工作区绑定**：通过 `/api/v1/workspaces/:id/bindings`（与 `pluginManager.resolveServiceSelection`）按工作区作用域确定性绑定同类驱动或协作插件，**不依赖插件加载顺序**。

- **契约产物校验**：`docs/plugin-api/*` 已由 `scripts/plugin-contracts.mjs` 同步更新并通过 `pnpm contracts:check`。

### 3.2 在途资源与代次隔离

1. **驱动在途句柄固定原提供方与代次**：
   - `HarnessRegistry.resolveAdapter` 与 `session-manager.ts`（`withDriverProvider`）在开启会话或恢复句柄时记录并校验 `providerPluginId`、`providerInstanceId`、`providerRunId`。
   - 切换工作区默认驱动绑定后，已在途会话与活跃句柄继续固定原提供方实例与 `runId`，仅后续新会话生效。
   - 原实例停用或重启时，清理该实例/代次的活跃子进程与动态注册服务，不越权操作其他实例。
2. **交接 `pending` / `confirmed` / `failed` / `uncertain` 语义**：
   - `outbound-gate.ts` 与 `context-compiler.ts` 在投递超时/结果不明时写入 `deliveryStatus = 'uncertain'`；后续编译与续接强制 `forceFreshNativeSession = true`（`forceFreshReason = 'uncertain_previous_delivery'`），**禁止自动静默重投**。
3. **移除宿主 Fallback，停用显式返回 `409 E_PLUGIN_DISABLED`**：
   - 已从 `packages/daemon/src/core/session-manager.ts` 彻底移除 `fallbackExplorer`、`fallbackOrchestrator`、`fallbackCompressor`。
   - 关闭任意协作/驱动插件后，标准聊天与基础运行不受影响（如关闭压缩或交接仍可继续基础对话），访问已停用插件功能通过旧兼容 URL 统一返回 `409 E_PLUGIN_DISABLED`。
4. **编排策略插件化与在途子任务结算**：
   - `maxDepth`、`maxConcurrent`、`defaultTimeoutMs`、`worktreePolicy` 收归 `orchestrator-default` 插件自有配置，移除内核 `HARD_MAX_DEPTH_CAP` 强制上限。
   - 停用 `hm.plugin.multi-harness-orchestrator` 时，`onPluginDisabled()` 同步将活跃子任务在 SQLite 中结算为 `stopped` 并触发中断信号，同时完整保留对应的 Git worktree 与分支供排查恢复。
5. **SQLite 解耦迁移（`packages/daemon/src/db/sqlite.ts`）**：
   - 幂等重建移除 `session_handoffs` 与 `subagent_runs` 对 `sessions(id)` 的外键耦合约束，支持协作数据与会话主存插件独立生命周期与恢复。

### 4.2 通过 Peer Router 解析并消费协作服务

```ts
import {
  PEER_CONTRACTS,
  type SessionCollaborationServiceV1,
  type SessionCompressionServiceV1,
  type SessionHandoffServiceV1,
  type SessionOrchestrationServiceV1,
} from '@harnessmate/plugin-api';

// 按作用域解析当前已启用并绑定的协作实例
const collabSel = pluginManager.resolveServiceSelection(PEER_CONTRACTS.sessionCollaboration, {
  workspaceId,
  sessionId,
  allowSingleCandidate: true,
});
if (collabSel.status !== 'ready' || !collabSel.instanceId) {
  throw new Error(`Collaboration unavailable: ${collabSel.status}`);
}
const collab = pluginManager.host.getServiceByInstance<SessionCollaborationServiceV1>(
  collabSel.instanceId,
  PEER_CONTRACTS.sessionCollaboration,
)!;

// 分叉 -> 回并 -> 导出便携包
const forked = await collab.forkSession({ sessionId, targetHarnessId: 'claude', title: 'Review Fork' });
if (forked.ok) {
  await collab.mergeBack({ childSessionId: forked.value.session.id, summary: 'Verified findings' });
}

// 消费编排服务（使用插件策略配置并关联 W1 session.data.v1 / B2 worktree）
const orchSel = pluginManager.resolveServiceSelection(PEER_CONTRACTS.sessionOrchestration, {
  workspaceId,
  sessionId,
  allowSingleCandidate: true,
});
if (orchSel.status === 'ready' && orchSel.instanceId) {
  const orch = pluginManager.host.getServiceByInstance<SessionOrchestrationServiceV1>(
    orchSel.instanceId,
    PEER_CONTRACTS.sessionOrchestration,
  )!;
  const limits = await orch.getLimits();
  if (limits.ok) {
    await orch.delegateTask({
      parentSessionId: sessionId,
      targetInstanceId: 'claude',
      roleTitle: 'Verifier',
      prompt: 'Audit diff and report summary',
      isolation: 'worktree_write',
    });
  }
}
```
