### 1.2 数据表与唯一写入者

#### A. `hm.plugin.session-data-default` 独占业务写入的 SQLite 表

- `workspaces`：工作区元数据，由 `hm.plugin.session-data-default` 唯一写入（`createWorkspace` / `deleteWorkspace`）。
- `sessions`：会话头、`last_seq`、`status`、`model`、`actual_model`、`usage_json`，由 `hm.plugin.session-data-default` 唯一写入。
- `session_events`：标准事件流与单调 `seq`，在事务边界内随 `last_seq`、`session_change_log` 同提交后通过 `ctx.services.publish('session.data.v1', ...)` 与 `DaemonEventBus` 发布。
- `turn_items`：轮次结构化块（TurnBlock），在事务内写入并记录 `session_change_log`。
- `session_runs`：运行记录（`started_at`、`ended_at`、`status`、`failure_class`），仅通过 `session.data.v1` (`commitBatch` / `recoverCrashState`) 写入。
- `session_harness_bindings`：多驱动原生会话 ID 与 handoff 水位（`native_session_id`、`synced_up_to_seq`、`driver_used`），并在 `nativeSessionId: null` / `syncedUpToSeq: 0` 时调用 `setSessionBindingExact` 精确重置。
- `session_import_mappings` & `session_import_receipts`：本地/导入包防重映射与请求幂等回执。
- `session_change_log`：全局已提交变更日志，驱动 `session.data.v1` 增量快照、分页与 B1/B2 投影游标（携带 `providerInstanceId` + `streamId` 身份）。
- `session_turn_receipts`：按 `(session_id, request_id)` 持久化的轮次发送请求幂等回执（`request_hash`、`turn_id`、`run_id`、`status`、`runtime_instance_id`、`runtime_run_id`）。

#### B. 宿主保留的内核 / 未迁移表（不绑定到私有 `workspaces`/`sessions` 外键）

- `resource_owners`：宿主通用资源归属索引 `(resource_type, resource_id, contract) -> (instance_id, workspace_id)`，用于跨实例工作区/会话后续操作精确路由与停用隔离。
- `plugin_permissions` / `plugin_global_permissions`：宿主权限矩阵；[sqlite.ts](file:///C:/Users/windfile/.gemini/antigravity/worktrees/harnessmate_desktop/session_data_runtime/packages/daemon/src/db/sqlite.ts) 已移除 `plugin_permissions.workspace_id` 对 `workspaces(id)` 的外键约束并自动迁移旧库，使外部 `session.data.v1` 实例的工作区同样可授予 `session:send`、`session:read` 等工作区权限。
- `session_task_state`：B2 任务账本表（暂由 `core.task-ledger` 管理）；[sqlite.ts](file:///C:/Users/windfile/.gemini/antigravity/worktrees/harnessmate_desktop/session_data_runtime/packages/daemon/src/db/sqlite.ts) 已移除对 `sessions(id)` 的外键约束并自动迁移旧库，[session-assistance.ts](file:///C:/Users/windfile/.gemini/antigravity/worktrees/harnessmate_desktop/session_data_runtime/packages/daemon/src/plugin-host/builtin/session-assistance.ts) 通过 `findSessionWithProvider` 兼容外部数据会话。
- `approvals` / Batch-4 原生表：保留宿主审批与 AGY native 表由 B4 迁移；构造函数仅在默认数据实例未被明确停用时处理历史未发布超时审批（Batch 4 领域）。

#### C. 外部纯 SDK 数据插件（`hm.plugin.session-data-lite`）

- 完全不访问宿主 SQLite；工作区、会话索引、分片事件 `events:<sessionId>:<chunk>`、轮次块 `items:<sessionId>`、运行记录 `runs:<sessionId>`、绑定 `bindings:<sessionId>`、幂等回执 `receipts:<sessionId>`、导入映射与变更桶 `changelog:<bucket>` 全部保存在插件 KV 存储，所有游标携带独立 `streamId`（格式 `kv-<instanceId>`）。

## 3. 供 W2 / W3 直接运行的消费示例

### 3.1 W2（Harness 驱动与协作实现）消费 `session.data.v1` / `session.runtime.v1`

W2 替换驱动或协作适配器时，可直接通过 `SessionManager` 窄端口 / HTTP 路由与 `session.runtime.v1` 驱动任何内置或第三方插件提供者（示例以独立 Node/TS 测试脚本运行）：

```ts
import { PEER_CONTRACTS, type SessionDataServiceV1, type SessionRuntimeServiceV1 } from '@harnessmate/plugin-api';
import { createDaemon } from '../src/server/app.js';
import { resolveSessionDataProvider, resolveSessionRuntimeProvider } from '../src/core/session-peer-router.js';

const daemon = createDaemon({ dataDir: 'D:/HarnessMate/b3-tmp/w1/w2-demo', port: 0, hostOverride: '127.0.0.1' });
await daemon.start();

// 1. 创建绑定到默认或第三方数据实例的工作区与会话
const ws = await daemon.sessionManager.addWorkspace(process.cwd(), 'W2-Demo', 'hm.plugin.session-data-default');
const session = await daemon.sessionManager.createSession({ workspaceId: ws.id, harnessId: 'codex', permissionMode: 'manual' });

// 2. 通过公开 Peer 契约直接读写数据与提交批次（W2 驱动侧或协作插件侧）
const data = resolveSessionDataProvider(daemon.pluginManager, { sessionId: session.id, workspaceId: ws.id }).service;
await data.commitBatch({
  sessionId: session.id,
  bindingUpsert: {
    sessionId: session.id,
    harnessId: 'codex',
    harnessKind: 'codex',
    nativeSessionId: 'thr_w2_demo',
    syncedUpToSeq: session.lastSeq,
    driverUsed: 'native_warm',
  },
  events: [{ type: 'handoff.system_notice', turnId: null, payload: { level: 'info', message: 'W2 driver bound' } }],
});

// 3. 通过 session.runtime.v1 发送幂等轮次并查询驱动确认配置与中断
const runtime = resolveSessionRuntimeProvider(daemon.pluginManager, { sessionId: session.id, workspaceId: ws.id }).service;
const receipt = await runtime.sendTurn({ sessionId: session.id, text: 'hello w2', requestId: 'w2-req-1' });
const replay = await runtime.sendTurn({ sessionId: session.id, text: 'hello w2', requestId: 'w2-req-1' }); // 返回 disposition: 'reused'
await runtime.interrupt({ sessionId: session.id, reason: 'w2_test_cancel' });
await daemon.stop();
```

WS 订阅携带流身份与跨流重置处理示例：

```js
ws.send(JSON.stringify({
  op: 'subscribe',
  sessionId,
  afterSeq: lastKnownSeq,
  stream: lastKnownStream, // { providerInstanceId, streamId }
}));
ws.on('message', (raw) => {
  const frame = JSON.parse(raw.toString());
  if (frame.op === 'replay_complete') {
    // 若切换了数据实例或重建了流，frame.streamMismatch === true，服务端已从 seq 0 重放全量事件
    lastKnownSeq = frame.lastSeq;
    lastKnownStream = frame.stream;
  }
});
```
