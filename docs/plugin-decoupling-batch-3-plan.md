## 3. 第三批完成后用户能做什么

1. 同一个应用里，工作区 A 使用默认会话与聊天插件，工作区 B 使用自己安装的实现。
2. 使用外部插件提供同类 Codex、Claude 或 ACP 驱动，无需修改宿主源码，也不需要冒用另一个产品名称绕开保留 ID。
3. 分别替换聊天、数据、运行、交接、压缩或编排实现；没有启用的可选功能不会在后台被宿主补建。
4. 插件可以改变会话流程、消息展示、Composer、命令和协作策略。需要新业务时，优先在插件自己的服务、页面和进程中完成。
5. 停用聊天视图不终止后台轮次；停用某个驱动只处理该实例持有的句柄；故障或回退后可以继续查看旧记录。
6. 第三批新旧版本之间保留原会话 ID、原生会话 ID、事件顺序、旧 API 以及可验证的数据回退能力。

本批不重写 Electron、Cordis 风格的装配机制、整个 Web 应用框架或全部数据库。默认插件也不能仅把旧宿主对象包一层后宣称完成。

### 5.2 身份、选择与正在运行的资源

必须区分以下身份，旧 ID 不因重构被改名：

- pluginId：可安装插件包。
- instanceId：插件提供方实例。
- harnessId：现有 CLI/账号实例，例如 codex 或 agy.work。
- driverId：协议/实现类别声明；多个插件实例可以声明同类驱动。
- runId：某插件的本次运行代次。
- sessionId、turnId、nativeSessionId：原业务身份。

一次运行保存 dataInstanceId、runtimeInstanceId、driverProviderInstanceId、harnessId 和相应代次/句柄引用。字段名称可对齐现有 DTO，含义不能混用。

新操作按明确实例、会话、工作区、依赖和组合的现有解析规则选择。正在运行的轮次继续交给原实例结算，不能在收到下一段 delta 时重新选择。显式选择已停用时显示不可用；不靠注册先后顺序暗中切回预装实例。

### 5.3 只补必要的通用原语

优先使用已有服务、路由、托管进程、桌面视图、存储与组合机制。确有缺口时，先记录失败调用路径，再补可供所有插件使用的原语：

1. 默认数据插件需要原 SQLite 连接上的事务时，补通用数据库/事务访问，复用连接与锁；业务表、迁移 SQL 和查询规则归数据插件。跨进程事务使用可序列化的事务批次，不传数据库对象或函数。
2. 页面需要持续接收事件时，补通用服务订阅，支持快照、游标、批量事件和释放。底层资源只识别实例、通道及代次，不识别“聊天 token”或“某厂商输出”。
3. 驱动和运行句柄沿用既有托管生命周期；缺少租约语义时补可释放的通用资源句柄。

可信本地插件沿用已授权的系统访问方式。无需为每个业务方法、每次 Shell 或每个页面新增权限弹窗、官方白名单、私有前缀或实现数量限制。实例归属、取消和可回退是运行保障，不用于限制同类插件并存。

## 6. B3-W1：会话数据与运行

### 6.1 数据插件接管真正的写入

- 将会话、工作区、事件、轮次块、运行记录、驱动续接绑定和已提交变更的操作归到默认数据插件。
- 默认实现原地读取旧表，保留原 ID、序列、导入映射和水位；首次启动的补齐操作应幂等。
- 沿用 hm.session-data.v1 的导入与搜索接口语义；历史导入、搜索、账本、Studio、收件箱和用量读取迁为公共契约调用。
- 会话创建、事件/块写入与对应变更日志在同一事务提交。发布事件发生在提交之后。
- 原会话所属的数据实例要能在未加载具体业务对象时定位，优先利用现有持久化绑定。需要补资源索引时采用通用的资源 ID → 实例映射，不在内核复制会话内容。
- 数据实例可以使用自己的存储。不能要求所有替代实现共享默认 SQLite、访问 daemon 内部 store 或读取另一个实例的私有表。
- 快照与变更游标带上提供方/数据流身份。切换到另一数据源后不能直接比较两边的 seq；搜索与账本等投影要按数据流重新衔接。
- 数据插件停用不会删业务表。其数据暂时不可用时，相关入口提供原因和恢复选择，不由宿主打开旧表冒充新实例。

### 6.2 运行插件接管轮次与句柄

- 迁移 liveHandles、activeTurnMeta、启动互斥、文本合并、运行恢复及会话关闭流程。
- 发送按 requestId 记录接收回执与 turnId；同一标识重试只能对应一个业务轮次。旧客户端不传标识时仍按原 API 工作，但不能自动重放结果未知的外部调用。
- 规范化驱动事件由运行插件交数据插件提交，保留既有 canonical event 与 TurnBlockRecord 的顺序语义。
- 配置变更区分请求值和驱动确认值；生效、等待新会话和不支持应有明确回执。
- 中断和完成之前先排空文本合并缓冲，最后一段不能丢；已完成轮次不能被迟到回调重新变成 running。
- 运行插件热更新先停止接新轮次，再结算或可控中断所持资源。不会把旧进程的输出接到新代次。
- 停用数据插件时先协调其依赖的写入，不能让运行轮次继续向已经撤销的数据实例发送写操作；失败和待恢复状态必须可查。

### 6.3 AGY、审批及兼容面

- 定义清晰的 NativeRuntimePort / RuntimeRequestPort 等衔接面，适配现有 AGY wiring 和审批记录。
- native ID、dispatch provenance、held settlement、审批回复与过期语义保持现状，不在第三批重新设计 AGY 业务。
- 第四批未迁移的 AGY registry、审批存储与 UI 在例外清单登记，不能用这些例外保留一个隐藏的通用 SessionManager 实现。
- 原 SessionManager 可暂留对外门面；其中本批迁出的操作只解析并转发，不持有备用服务、驱动业务状态或数据库写入。
- HTTP 和 WebSocket 保留旧路径、字段、分页、状态码及断线续读行为。会话资源后续操作必须找到它的持有实例。

### 6.4 重点文件与交付

重点入口：server/app.ts、server/ws.ts、core/session-manager.ts、core/history-import-adapter.ts、core/session-change-feed.ts、db/sqlite.ts、server/routes/history-import-compat.ts、B1/B2 数据消费适配。

交付：默认数据/运行插件的 manifest、可加载入口、契约与迁移记录；外部 session-data-lite 和 session-runtime-lite 样例；数据表与唯一写入者表；兼容路由；测试和报告。

验收链：旧会话打开 → 发一轮 → 连续输出 → 中断 → 再发送 → 重启恢复；另一个工作区绑定外部数据/运行实现完成同样流程。停用其中一方后，其他工作区仍可运行。

## 7. B3-W2：通用驱动与协作

### 7.1 驱动获得真正平级的注册与选择

- 将 CodexAppServerAdapter、ClaudeStreamJsonAdapter、通用 AcpAdapter 的创建、CLI 配置与销毁放入各自插件。
- 改造驱动目录：以插件实例及声明 ID 管理注册，不用全局 Map 的一个 codex 键决定所有会话的实现。
- 移除“第三方不能提供内置驱动类别”的硬编码分支；runner-bootstrap、isolated-manager 和旧测试一起更新，避免只放开前端声明。
- 同包两个实例可使用不同 CLI 路径、home、账号与配置，不能从同一全局代理对象取配置。
- 旧 codex/claude/acp 和配置中的 harnessId 由默认组合、别名和既有绑定延续；AGY 原生实现保持当前提供方，第四批再完成其领域迁移。
- 外部驱动使用公开 SDK 即可被标准会话入口选择。驱动公开注册和内部适配只能有同一份身份与资源账本。
- 模型、Plan、Goal、压缩、额度、原生插件与 Skills 等操作从驱动能力和命令目录声明；未提供的能力展示其真实状态，不伪装执行成功。

### 7.2 迁出协作业务及隐藏回落

- ContextCompiler、handoff-snapshot/redactor/outbound-gate 的业务部分由交接插件拥有；保留待投递、确认及结果不明的现有语义。
- ContextCompressionService 的后台 rollup、配置和任务随压缩插件启停；基础聊天不依赖它。
- 从 SessionExplorerService 中移出分叉、合并、Side Chat、导出等剩余协作部分，继续保留 B1 导入/搜索的插件归属。
- OrchestratorService 的子任务、唤醒、超时、Git worktree 和状态恢复由编排插件拥有，通过 W1 运行契约创建、发送和中断。
- 清除本批功能的 fallbackExplorer、fallbackOrchestrator、fallbackCompressor。保留旧 URL 可以，保留宿主业务备用实现不算完成。
- 把现有编排深度、并发数、超时和工作树策略保留为默认插件的行为/配置；公共 SDK 和内核不以这些默认值限制其他实现。
- 交接、压缩和调度分别可停用。停用后聊天、历史和其他协作插件继续可用；在途任务按持有实例完成结算。

重点入口：harnesses/{registry,types,codex-adapter,claude-adapter,acp-adapter}.ts、plugin-host/builtin/services.ts、isolation/{isolated-manager,rpc-router,runner-bootstrap}.ts、core/{context-compiler,outbound-gate,context-compression-service,session-explorer-service,orchestrator-service}.ts。

## 8. B3-W3：聊天界面、性能与完整候选

### 8.1 默认聊天成为普通可替换插件

- 把 ChatStage、Composer、消息/工具渲染、会话命令、草稿及其业务 store 迁入默认聊天插件。
- 现有 App 只按当前作用域的选择挂载页面。缺少聊天实例时显示可恢复的不可用状态，不回落到宿主 ChatStage。
- 默认聊天和外部聊天走同一页面/服务路径；不保留默认插件的 React 特判，外部插件也不要求访问宿主私有 Zustand store。
- 复用现有 HTML/JS/CSS 页面资源机制，把原 React 视图构建成插件自己的前端产物。不要把整个宿主 app-store 重新打进 iframe 后再启动第二条独立全局 WebSocket。
- 数据与运行操作通过通用服务调用/订阅桥。若采用可信模块挂载等其他现有模式，必须证明外部实现可以使用相同模式，且能完整撤销。
- 完整迁移现有输入、附件、终端引用、Windows 文件链接/行号、Markdown、代码块、复制导出、模式/模型选择、插件开发模式、命令和流式状态。
- 整体 Sidebar、应用设置、插件中心和远程界面仍按第五批处理；本批将会话列表动作与会话业务状态改成调用 W1，不复制进另一套全局 store。

### 8.2 订阅与切换

- 页面首次获取快照及边界游标，随后订阅并补齐；加载和实时输出同时发生时不丢事件。
- 以提供方、runId、sessionId 和游标区分订阅，处理重复、间隙、重连和迟到响应。
- 批量传递事件，避免逐字符跨桥或每段 delta 重发完整历史；订阅取消后释放监听和队列。
- 换聊天视图只更换显示者，不中断运行插件持有的轮次。恢复页面时按已提交事件追补。
- 草稿、附件引用和滚动位置由视图显式保存/交接；插件临时不可用时可以恢复草稿，不自动发送。
- 外部聊天样例必须能读取历史、发送、中断、显示持续输出和打开文件；只有一个标题页面不算替换成功。

### 8.3 性能验证

先用固定输入复测 B2，再测 B3；不依赖真实模型吐字速度来判断前端性能。

建议固定夹具：10,000 条历史事件、60 秒持续流式输入、25 批/秒、工具输出与中文代码块混合，另设多个后台会话并行更新。记录夹具大小、测试机器、构建模式和至少三次运行的中位数及 P95。

分别记录：
- 驱动事件进入运行插件、事件提交、WebSocket 接收、页面可见更新四个时间点。
- 首段可见延迟、接收到可见的 P95、每秒可见更新次数、最长无刷新间隔。
- 超过 50ms 的主线程长任务、堆内存变化、插件订阅数量和未处理队列长度。
- 切会话、打开文件和停止输出时的交互延迟；与终端满缓冲复验一起保留。

**拟定预算，尚未实测：** 正常前台流式场景从页面收到事件到可见更新 P95 ≤ 100ms；从运行插件接收固定驱动事件到可见更新 P95 ≤ 200ms；连续有输入时不出现超过 500ms 的可见停顿；每项相对固定 B2 基线的回归不超过 10%。短交互和历史加载也做同机对照。

应同时满足绝对体验预算和相对对照。基线已慢不能成为放行理由；预算需要调整时先提交测量、瓶颈与替代预算，再更新方案，不能在测试失败后悄悄改阈值。

### 8.4 交付

默认聊天插件、外部 chat-lite 样例、通用调用/订阅桥、迁移后的业务状态、固定性能回放脚本、Web/daemon 集成回归、Windows 候选 EXE、旧包回退记录、完整报告。

本会话负责最终接线和打包，不接管 W1/W2 未完成的业务开发；集成发现问题按所有者修复。

## 10. 数据所有权与回退

| 数据/资源 | 本批目标所有者 | 保留内容与恢复要求 |
| --- | --- | --- |
| workspaces、sessions、session_events、session_turn_items、session_runs、session_harness_bindings | 默认数据插件；运行插件通过其 API 写入 | 原主键、序列、native ID、配置及运行记录；升级后可由 B2 旧包读回 |
| 导入映射、回执、session_change_log | 数据插件提交；导入/搜索插件仍拥有各自业务 | 保留幂等身份和水位；快照与变更属于同一已提交数据流 |
| context snapshots、session_handoffs、压缩状态、分叉关系、subagent_runs | W2 对应业务插件 | 按同一连接事务或明确的可恢复协议关联会话；结果不明不能自动重复投递 |
| 任务账本、收件箱、提醒和额度数据 | 原 B2 插件 | 不在会话迁移中复制所有权；改成使用公开会话数据/运行契约 |
| CLI 进程、adapter handle、实时订阅和合并缓冲 | 持有它们的驱动/运行实例 | 当前代次负责释放；停用不影响另一实例的进程和轮次 |
| 草稿、视图偏好、展开状态 | 聊天插件 | 沿用或幂等导入旧键；切换/回退不自动发出草稿 |
| approvals、AGY native 表和语义 | 既有审批/AGY 领域，第四批迁移 | 第三批通过衔接面保持原 ID、过期状态及 native 路由，不擅自迁库 |

数据实例在同一存储中的唯一写入权只针对同一资源，不是同类插件的全局互斥。多个实现可同时管理各自会话；主动共享同一份会话的数据切换需要交接所有权。

回退按三档实测：单实例停用并恢复；插件修订或组合回退；最终 B3 EXE 升级旧数据副本后，使用真实 B2 EXE 读回 B3 新写入的会话与事件。外部 CLI 已执行的命令、Git 提交和账号配置变更不以数据库回退冒充撤销。
