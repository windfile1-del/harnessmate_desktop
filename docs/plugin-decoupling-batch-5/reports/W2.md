## 3. 公开 API 与兼容

详细示例：[SDK 管理/开发指南](../../plugin-api/management-development.md)。

- W1 `bridge.navigation` / `navigate`、`contributions`、`surfaces`、`kernel` 是唯一跨插件 UI 接缝。设置消费任意所有者 `settings` 贡献；既有 `harness.settings` 通过公共 surface mount。增加公共 render failure 读取/清理原语，管理插件不导入私有 slot registry。
- `GET /api/v1/plugins/settings`、`GET/PUT /api/v1/plugins/:instanceId/settings`：schema/version、owner config、视图描述；PUT 校验基础类型/预期修订/schema，并应用实例配置，保留包名/启停/依赖绑定。
- `GET/PUT /api/v1/plugins/host-config`：通用端口与数据根。启动变化返回 `restart_required` 和实际 executable/args/env；数据根用新进程环境选定，保留原目录，不假装普通 restart 会迁移数据。
- 现有 `/plugins`、`/plugins/preview`、`/plugins/install`、`/plugins/:id`、`/rollback`、`/composition/*`、`/dev/*` 供默认、外部管理与恢复同等调用。
- 可选 `ctx.runtime.requestHost({path,method,body})` / `runtime.dataDirectory`：可信本地实例的通用 HTTP loopback 和实例持久目录；RPC 检查 trusted-local、当前 instance/run、本地 `/api/v1/` 路径、拒绝路径穿越并在响应后再查代次，不暴露凭证或私有 store。外部 trusted dev 包使用相同路径。没有新逐业务授权墙。
- 新服务名 `management.view.v1`、`developer.tools.v1` 是普通有命名空间的服务；没有加到业务 service:provide 授权名单。预装可信本地开发工具沿用原发行来源信任元数据。
- 旧 `/plugins/builder-v2/generate` 等开发 URL 不再常驻，返回 404。已有 domain API 没有因本包重做。

## 4. 配置映射与回退

| 旧字段 / 功能 | 实例所有者 / 新权威 | 兼容 |
| --- | --- | --- |
| binaryOverrides[driver] | `pluginConfig['harness-'+driver].binaryPath` | 保留 B4 镜像 |
| harnessInstances | 按 driver 所有者的 `instances` | 原账号/实例 ID 保留；不重建绑定 |
| customAcpHarnesses | harness-acp.customHarnesses | 旧 API 通过动态 getter/setter 写回同一 map |
| agyProfiles | harness-agy.profiles | 替换 owner bucket 后 getter 不读旧闭包 |
| 主题 | 选定 layout instance 的 theme schema | 通用内核只负责应用颜色，不定义主题产品方案 |
| 端口、数据根 | 通用 host startup | 数据根切换返回可执行新进程参数 |
| 策略、终端、远程等现有领域状态 | 原领域视图/服务/存储及任意 instance JSON 配置 | 不复制新的中央配置；远程生命周期由 W3 收尾 |

激活配置优先级为 owner map → 显式 composition config。设置保存读取合并值，写 owner map 并清空该实例 composition override，避免旧账号数组遮蔽 B4 API 更新；保持 bindings/disabled。组合编辑仍可显式写覆盖。旧字段非枚举兼容访问器，save 输出 B4 字段镜像。适配器只遍历对应 Harness 所有者，保留其他第三方插件同名 instances 字段；清除旧 binaryOverrides 也正确移除对应 owner binaryPath。ACP 的 customHarnesses schema 同时接入实际实例加载。

回退分层：停用释放运行资源且保留数据；上一修订回退代码；组合恢复回退 entries/bindings/显式覆盖；owner config 需配置副本回退，组合不会撤销所有数据写入。B4 格式测试不等同于真实 B4 EXE 读回数据副本，后者归 W3。

## 5. 开发链与任务语义

- 生成/Authoring 路由位于 `/api/v1/plugin-instances/:toolInstance/routes`；`/context`、`/tasks`、`/tasks/:id`、`/tasks/:id/cancel`、`/install`、`/audit`、`/scaffold`、`/preview/program`、`/preview/replay` 随工具实例启停。
- 每实例单个生成任务；客户端 taskId 幂等，重连不重复执行。状态包含 instanceId/runId、closePolicy、诊断/生成文件/digest。journal 为实例目录 tasks.json，有界保留 60 条。
- 默认关闭页面取消；可明确选后台继续后从任务列表读取。显式取消始终中止；关闭与任务启动确认竞态重复送取消以免漏取消。插件停用取消所有工作；进程中断后重新加载将运行任务标为 cancelled，不自动恢复。完成草稿可从 journal 按原文件/digest 安装，无需重新生成。
- 构建保留原四阶段（schema/结构、静态审计、Node 语法、mock 激活/CSP），最多三轮自修复。安装重新物化审阅快照并验证，阻止内存文件与旧磁盘快照错配。
- 首次 dev 来源必须确认可信源码目录；同一真实目录与 ID 的重载/再安装使用已有授权。普通 local install 继续原代码包预览/digest 信任。停用不会删除开发目录。
- 安装结果返回应用状态、是否重启及真实贡献页面；可直接预览、选择能力绑定、编辑目录热加载。坏修订不提交，last-good 可用，支持上一修订/组合恢复。
- 开发模式只在该用户消息附带 SDK/version/features/providers/目录/安装停用信息，不替换系统提示词。已删除 session-manager 与 host-runtime-ports 对后续普通消息持续追加开发 brief 的行为。
