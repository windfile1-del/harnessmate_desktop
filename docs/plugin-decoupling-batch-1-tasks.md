# 第一批开发任务 · 历史导入与会话搜索

**本批待分派。** 本批把历史发现、导入和搜索迁为通过组合装配的平级插件，保留已有会话、导入行为和旧 API。用第三方来源和两种搜索实现证明扩展路径可用。本批范围对应总方案第 6 节。 [全量解耦实施设计](plugin-decoupling-implementation-plan.md)

## 1. 分工与开发基线

- **总指挥（Codex）**负责确认范围、裁定接口与数据所有权、处理跨任务阻塞、独立复验并给出合并结论。开发人负责实现、测试、提交和修复。集成人负责整合、打包并提供候选产物。每个任务可由同一人兼任，交付责任按任务编号追踪。
- **交接起点**是工作区中已经具备平级插件能力的版本。制定任务时本地 `main` 的 HEAD 为 `9eee791`，平级插件实现仍有未提交改动。由基线维护者提供包含这些实现的可复现提交或明确的基线快照，记录它包含的文件与测试结果。各开发人以同一份基线开工，集成按这一基线核对差异。
- **本批边界**是来源、导入、搜索及其页面和装配。会话写入暂由现有会话数据层通过适配器提供。分叉、Side Chat、原生审批、AGY 工作台及应用布局的全面迁移留在已排定的后续批次。浏览器和查看器作为平级装配回归样本。
- **开发交接**每项给出提交或 PR、契约变更、验证命令与结果、复现步骤、已知限制。共用文件由表中的责任人整合。暂存、夹具和 Windows 验收目录使用 D 盘。

## 3. 先确认的接口和数据边界

| 接口 | 请求与响应 | 所有者和交接点 |
| --- | --- | --- |
| `history.source.v1` | `discover` 接收过滤条件和分页位置，返回来源身份、原生会话 ID、标题、时间和工作区线索。`read` 按同一来源的会话引用返回可分页条目、读取状态和续读位置。 | B1-02。由来源解释四类信息，即格式、路径、账户和读取状态。调用方传来源引用，来源自行解析本地文件。 |
| `history.import.v1` | `preview` 返回选中的来源、已有归档、目标工作区及可导入内容。`import` 提交同一来源引用和导入参数，返回对应的会话 ID、创建或复用状态。 | B1-03。导入插件编排读取，现有会话数据层通过窄接口提交事务。 |
| 会话数据适配 | 保留创建会话、导入映射与回放事件所需的事务。提供一致性读取或可对齐的快照位置，以及从该位置继续读取已提交变更的接口。 | B1-03 持有原始数据，B1-04 读取会话投影。先复用当前存储和事件能力，再确定最少的接口改动。 |
| `session.search.v1`（建议） | `query` 接收关键字、工作区、驱动、时间范围及分页参数，返回会话、轮次、条目 ID 和展示片段。`reindex` 启动当前实例的重建任务，返回任务状态或兼容响应。 | B1-04 拥有索引、进度与存储。B1-05 使用结果身份跳转现有会话。 |

B1-01 汇总公共 DTO、契约版本、实例解析结果和错误语义的变更。旧端点的请求、响应、错误处理和现有限制以共同基线为准。新接口需要区分未配置、多个候选待选择、已绑定实例未就绪、来源无法读取和取消。负责双方确认这些语义与回归夹具后再跨任务联调。

## 4. 开发任务单

### B1-01 · 实例选择与组合默认项

1. 复用现有服务目录及 `ctx.provide`、`ctx.services.list/call`、实例路由和页面注册。新接口按显式实例、会话或工作区选择、调用方依赖绑定和组合默认项解析，作用域适用时才参与。只有一个兼容候选且该入口允许自动选择时，可以直接使用。多个候选返回可选实例。显式绑定不可用时保留绑定及状态。
2. 将仍由源码指定的出厂提供方改为由发行业务组合声明。兼容旧组合和 SDK 调用，列出仍使用旧解析的调用方。使可信本地插件与预装插件共用第一批所需的服务、路由和工作页注册路径。
3. 提交公共契约及生成文档。测试反转载入顺序、同一包多实例、已选实例停用再启用、版本不兼容，以及空组合与旧组合恢复。覆盖原有浏览器、预览和审批策略绑定的回归。

相关入口见 [绑定解析](../packages/daemon/src/plugin-host/composition/bindings.ts)、[服务目录](../packages/daemon/src/plugin-host/runtime/lifecycle.ts) 和 [组合配置](../packages/daemon/src/plugin-host/composition/profile.ts)。

### B1-02 · 本机历史来源插件

1. 复用当前扫描和解析模块，迁出 Codex、Claude、AGY 的发现和读取注册。每个实例配置自己的账户目录或来源根，输出稳定来源身份与原生会话 ID。AGY CLI 与桌面来源各自独立。Codex CLI 与桌面产物按实际文件格式验证，共用记录时保留同一去重身份。
2. 将现有缓存、分页和读取状态随实例管理。单来源出错只影响该来源，可单独刷新或停用。停用时停止新的扫描并取消可取消的读取。保留原生历史只读行为以及读取上限对长历史的提示。
3. 提供来源矩阵，逐项列明发现和正文解析的实测范围。Codex CLI、Codex 桌面、Claude CLI、AGY CLI、AGY 桌面分别记录格式版本、样本和结果。找不到期望的桌面会话时，记录实际查过的索引、目录或格式及返回状态。用公开契约实现一个可独立安装、启用和停用的自定义来源，和预装来源同时运行。

相关入口见 [历史扫描器](../packages/daemon/src/harnesses/history-scanner.ts) 和 [AGY 历史读取](../packages/daemon/src/harnesses/agy/native/recovery/history-source.ts)。

### B1-03 · 导入插件与会话事务

1. 把预览、来源选择、原生历史导入和归档包导入接入导入插件。读取调用固定到用户所选来源。旧接口分别保留发现、导入和归档包入口，新旧入口调用同一实现。保留旧接口的 native 会话身份、导入模式和本机导入条件。
2. 复用现有 `importSession` 写入逻辑。提交边界内完成去重查找、会话身份、原生映射及回放事件的写入。旧映射可以识别同一份原生记录。两个独立来源中碰巧同名的记录可分别处理。并发、重试和提交后断线应返回相同的已归档会话 ID。取消在提交前结束，已开始的提交以事务结果为准。
3. 以现有会话数据层作为本批唯一写入者，同时交付搜索所需的已提交变更读取。停用导入插件后现有会话可以继续打开、回放、搜索和导出。验证旧数据副本的导入与回退，记录追加的迁移和兼容说明。

旧路由包括 `/api/v1/harnesses/discovered-sessions`、`/api/v1/harnesses/import-session` 和 `/api/v1/sessions/import-bundle`。 [会话浏览服务](../packages/daemon/src/core/session-explorer-service.ts) · [现有会话存储](../packages/daemon/src/db/sqlite.ts) · [旧路由入口](../packages/daemon/src/server/app.ts)

### B1-04 · 会话搜索插件与可重建索引

1. 迁出查询、重建任务和默认 FTS 实现，保留工作区、驱动、时间筛选、分页及结果跳转所需的身份。旧查询和重建 API 转发到所选实例。按实例管理索引及进度，并给出另一种小型搜索实现用于成品切换验证。
2. 用会话已提交的变更替换直接索引更新。索引和同步位置一同提交。补建后续读快照期间的新增、更新和删除，使用稳定条目 ID 幂等处理。给出断电或崩溃后的续读验证，覆盖搜索停用期间产生、更新或删除的数据。
3. 重建可以取消或续跑。停用停止订阅和后台任务，隔离查询错误。开启第二个搜索实例后，两个工作区可以独立选用，重建和停用其中一个对另一个的索引无影响。

旧路由为 `/api/v1/search/sessions` 和 `/api/v1/search/reindex`。 [既有搜索实现](../packages/daemon/src/core/session-explorer-service.ts) · [旧路由入口](../packages/daemon/src/server/app.ts)

### B1-05 · 导入页、搜索页和导航兼容

1. 复用现有浏览、搜索和导入界面，分别接到插件注册的工作页和入口。预装组合复现原入口，原快捷入口指向插件页面。状态与后端使用同一实例解析结果，区分不可用、配置缺失和可切换实例。
2. 在导入页显示各来源，完成刷新、预览、选工作区、提交、取消、打开既有归档的流程。来源失败或停用只影响对应入口。搜索页呈现实例、筛选、分页、索引状态和结果跳转，保留已有的会话及轮次身份。
3. 切换或停用实例时，清理对应页面订阅和在途请求。验证聊天、已有会话打开、浏览器、文件预览能继续工作。验证旧菜单和命令入口、无结果、搜索关闭后恢复、同类实例切换与中文关键词。

相关入口见 [原会话浏览界面](../packages/web/src/components/SessionExplorerModal.tsx) 和 [插件工作页](../packages/web/src/slots/PluginWorkspace.tsx)。

### B1-06 · 装配、兼容和 Windows 候选包

1. 将来源、导入及搜索装配成发行组合，接入旧路由适配。核对宿主入口经组合加载这三个功能，空业务组合的恢复界面仍能装回原组合。本批临时保留的会话数据适配器写入开发记录，便于后续迁出。
2. 制作可复现的 x64 Windows 便携包，记录提交、包路径、启动参数、插件版本和隔离数据目录。用旧版数据副本跑默认组合、自定义组合和回退。保留来源矩阵、迁移前后导入映射与相关会话 ID、索引水位、关键日志或截图。验收副本放 D 盘，实际用户数据目录作为只读来源。
3. 提交候选证据并把已知问题关联到任务编号。任何失败项处理后使用同一流程复测，说明更换了哪些提交或产物。

## 5. 总指挥验收表

总指挥对同一个候选提交和 Windows 包独立复验。每项记 `PASS`、`FAIL` 或 `BLOCKED`，带可重跑步骤及证据。自动化夹具、桌面成品交互和真实来源验证分别记录。

| 验收门 | 通过条件 | 所需证据 |
| --- | --- | --- |
| A1 · 可复现交付 | 同一基线下契约一致，构建、类型检查、全量测试通过 | `pnpm contracts:check`、`pnpm build`、`pnpm typecheck`、`pnpm test` 的实际退出码与失败说明。公共契约变更时先生成文档。 |
| A2 · 插件所有权 | 候选包从默认组合装配来源、导入、搜索。停用三个入口分别停止其 UI、路由或任务。自定义来源和替代搜索均可独立接入 | 组合与实例清单，停用前后生命周期和请求结果。同一个发行包上安装替代插件的交互记录。 |
| A3 · 选择与并存 | 两个来源实例的结果独立，两个搜索实例按工作区选择，加载顺序颠倒后显式选择一致 | 双实例自动化用例，以及 Windows 上实际切换和复查结果。 |
| A4 · 导入可靠性 | 旧数据、归档包和新导入均可回放。并发或失败重试只保留一个对应会话，提交前取消无残留。停用后已归档会话仍可读 | 五类来源矩阵、稳定会话 ID 与事件计数、旧数据迁移对照、导入异常恢复用例。 |
| A5 · 索引可恢复 | 搜索关闭期间能导入、编辑和删除会话。恢复后查询反映这些变化。重建中断后可继续，旧链接仍可打开正确会话和轮次 | 重建前后变更数与索引位置，UI 打开结果，删除重放和中止恢复用例。 |
| A6 · Windows 与回退 | 默认和自定义组合都可启动，停用和回退后数据仍能打开。原浏览器与文件预览继续按实例运行，预览保留行号 | 打包运行记录、交互步骤、旧版数据副本、回退前后的版本和绑定。来源样本分真实脱敏产物和合成夹具。 |

重点复跑现有 [daemon 平级装配测试](../packages/daemon/tests/plugin-peer-assembly.test.ts)、[会话浏览与审批回归](../packages/daemon/tests/session-explorer-approval.test.ts)、[Web 平级插件测试](../packages/web/tests/peer-plugins.test.tsx) 和 [Web 会话浏览回归](../packages/web/tests/phase2-explorer-approval.test.tsx)。成品打包使用现有 `pnpm pack:exe` 流程。客户端和模型实际登录的覆盖范围按实测记录，CLI 夹具和桌面样本各自出具结果。 [上一批打包与实机记录](plugin-extension-recovery-plan.md)
