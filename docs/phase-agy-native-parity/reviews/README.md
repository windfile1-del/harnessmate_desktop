# 独立审查与验收表

每个任务写 `NP-XX-review-<shortsha>.md`，独立评审人使用开发报告及实际 diff。失败反馈给相应 owner，并重新审查新 SHA。进入 G2/G3/G4 时同法写集成审查件。

| 项 | 填写内容 |
| --- | --- |
| 目标 | Task ID、Capability IDs、基线与被审 HEAD、应用分支 |
| 范围 | 实际涉及路径与可写范围、共享契约 revision、迁移序号、争用或待审接口 |
| 证据 | Evidence ID、来源、AGY 版本/协议、App/CLI/OS、授权账号类别、模式、复现命令 |
| 正确性 | 生命周期、取消、异常、乱序、并行、权限、可回滚测试，逐项列结论 |
| 回归 | 旧 DB 和客户端、其他 Harness、Plugin SDK、Handoff、Orchestrator、重复用户操作 |
| 质量 | 哪些场景真实、哪些合成/回放、缺口及等级。是否有 UI 假状态或不必要权限 |
| 结果 | 可合并/修改后复验/上游受限/待授权，发布 gate、回滚命令及负责人 |

按 [测试策略](../12_Test_Strategy.md) 和 [矩阵](../02_Capability_Matrix.md) 审核级别。文件中仅保留脱敏链接、样本与官方来源。App 的截图或视频须来自专用工作区，能查到行级证据但不含账号、路径、私有提示及产物。审查者不直接修改其他任务的实现。
