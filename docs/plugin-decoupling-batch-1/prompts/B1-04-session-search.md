# 开发提示词 · B1-04 会话搜索与索引

你是 HarnessMate Desktop 第一批解耦的搜索开发人。请**实现独立的 FTS 搜索插件和一个同契约的替代搜索实现**，验证索引可重建、两个实例可并存。总指挥负责接口裁定、独立验收和合并结论。 [任务单](../../plugin-decoupling-batch-1-tasks.md)

## 开工

在 `D:\HarnessMate\harnessmate_desktop` 相关开发目录核对 `git status -sb`、HEAD 和共同基线，保留工作区已有用户改动。使用 B1-01 确认的搜索契约，与 B1-03 对齐一致性快照和已提交变更读取。读模型尚未接入时，用同契约的夹具验证投影算法和查询。临时文件与索引副本放 D 盘。

先读 [现有搜索服务](../../../packages/daemon/src/core/session-explorer-service.ts)、[SQLite FTS 查询与写入](../../../packages/daemon/src/db/sqlite.ts) 及 [现有路由](../../../packages/daemon/src/server/app.ts)，确认当前筛选、分页、排序、兼容行为与索引更新调用点。

## 实现要求

1. 复用现有 FTS 查询、过滤及结果格式作为默认实现。插件拥有查询、重建任务、索引状态与同步位置。保留工作区、时间、驱动和分页语义以及跳转所需的会话、轮次、条目 ID。和 B1-05 对齐查询结果和进度状态。
2. 消费会话数据层已提交的新增、更新和删除。全量补建以一致性快照开始，随后按对应位置续读。索引与同步位置一同提交，按稳定条目 ID 幂等处理。覆盖重建中的并发写入、停用期间变化、崩溃重启和删除后重放。索引存储及游标各自按实例归属。
3. 启停按插件生命周期管理查询入口、任务和订阅。切换或重载时及时结束旧代次任务。两个搜索实例能按工作区选择，单实例停用和重建不影响另一实例。替代实现应通过同一公共契约独立注册、安装和切换。
4. 提供 `/api/v1/search/sessions`、`/api/v1/search/reindex` 的兼容适配。将 legacy 直接索引调用点和替换方式交 B1-06。会话事实数据由 B1-03 所属的数据层维护，索引由本任务维护。共用存储和挂载文件按任务单协调集成。

## 自测与交付

- 验证旧筛选、分页、中文关键词、结果跳转，覆盖两个搜索实例和两个工作区。暂停后创建、更新和删除会话，恢复后比对结果。注入重建取消和进程中断，记录索引与同步位置的恢复过程。
- 运行适用的 daemon 回归、类型检查和差异检查。旧 API 与默认插件的查询结果以同一夹具对照。说明未覆盖的来源或规模。
- 交付基线、任务提交或 PR、默认和替代插件、实例配置、已提交变更用法、索引重建与恢复的复验步骤、实际测试结果和兼容挂载说明。由总指挥独立复验并给结论。
