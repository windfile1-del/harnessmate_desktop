# 开发提示词 · B1-06 集成与 Windows 候选包

你是 HarnessMate Desktop 第一批解耦的集成与打包开发人。请**整合 B1-01 至 B1-05，制作 Windows x64 便携候选包并交付可复验证据**。你负责集成自测，独立验收与合并结论由总指挥负责。 [任务单与验收表](../../plugin-decoupling-batch-1-tasks.md)

## 开工

在 `D:\HarnessMate\harnessmate_desktop` 相关开发目录核对 `git status -sb`、HEAD、共同基线和总指挥确认的任务提交。验收目录、旧数据副本和打包暂存放 D 盘，生产数据目录只作只读来源。依赖提交未齐时先准备打包入口和测试夹具。候选从固定集成提交构建，保留其他开发人的工作区与任务提交。

## 集成要求

1. 按宿主与契约、来源和导入事务、搜索与 UI、发行组合的顺序整合。统一在 daemon 挂载旧 API 兼容适配。把历史来源、导入和搜索加入发行组合并核对其加载和停用归属，标出本批暂用的会话适配器以及要在后续批次接走的调用。
2. 确认默认组合装回原入口，自定义组合可以同时启用多个来源和搜索实现。实际停用、重启、恢复及回退。验证旧工作区、会话和归档包可打开，已导入的会话保留原身份，索引可续读并更新。空业务组合能进入恢复界面并重新装回正常配置。
3. 使用 `pnpm contracts:check`、`pnpm build`、`pnpm typecheck`、`pnpm test` 和 `git diff --check` 验证候选。公共契约有变更时先确认已生成文档。使用现有 `pnpm pack:exe` 流程打包，在独立数据目录启动成品执行交互。打包步骤与仓库脚本不一致时，记录实际运行的命令、依赖和原因。 [上次打包与实机记录](../../plugin-extension-recovery-plan.md)
4. 按任务单 A1 至 A6 做集成自测。覆盖第三方来源与替代搜索的安装、同类并存、反转加载顺序、并发导入与取消、停用期间索引变更、中文搜索打开结果、组合恢复、浏览器与文件预览回归。分别记录五类历史来源中实际跑过的 CLI、桌面脱敏样本和合成夹具。
5. 缺陷按 B1-01 至 B1-05 退回领域负责人，并注明复现步骤与影响。修复后从新的固定提交重新构建和复验受影响项。集成提交、候选包和验收记录交总指挥审阅，由其给合并结论。

## 交付给总指挥

- 共同基线、集成提交、包含的五个任务提交及待处理差异。
- 便携 EXE 完整路径、版本、签名状态、构建命令、插件清单、启动参数和 D 盘验收目录。
- A1 至 A6 的自测结果、实际命令和退出码、UI 操作记录、来源矩阵、脱敏日志或截图。区分 `PASS`、`FAIL`、`BLOCKED`，并写明每项证据适用的提交和包。
- 数据与配置回退步骤、回退后验证结果、已知限制和相关任务编号。总指挥应能用同一个候选包和同一副本重复运行关键用例。
