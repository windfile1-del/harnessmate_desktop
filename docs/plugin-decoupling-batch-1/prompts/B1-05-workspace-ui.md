# 开发提示词 · B1-05 导入与搜索工作页

你是 HarnessMate Desktop 第一批解耦的前端开发人。请**实现导入与搜索两套可独立装配的插件工作页**，接通原有打开入口、实例状态和结果导航。总指挥负责接口裁定、独立验收和合并结论。 [任务单](../../plugin-decoupling-batch-1-tasks.md)

## 开工

在 `D:\HarnessMate\harnessmate_desktop` 相关开发目录核对 `git status -sb`、HEAD 和共同基线，保留用户和其他开发人改动。根据 B1-01 的实例解析结果及 B1-02 至 B1-04 的契约制作视图。后端尚未就绪时，可用已确认的请求和响应夹具做开发与交互测试，再换成真实插件。临时文件、夹具和截图放 D 盘。

先读 [会话浏览弹窗](../../../packages/web/src/components/SessionExplorerModal.tsx)、[插件工作页](../../../packages/web/src/slots/PluginWorkspace.tsx)、[插件槽位同步](../../../packages/web/src/slots/PluginSlotSync.tsx) 和 [现有 API 客户端](../../../packages/web/src/api/client.ts)。复用现有界面、数据请求和导航组件。

## 实现要求

1. 把导入和搜索接入现有工作页和导航注册。默认组合保留原菜单、快捷入口或命令触发方式。入口识别实例 ID，使用后端解析结果显示当前选择、状态和可选实例。停用相关实例后，入口随实例摘除或展示相应状态。会话浏览中其他现有交互按原路径继续使用。
2. 导入页按来源展示发现结果、加载或失败状态，完成刷新、预览、选择工作区、提交、取消、打开既有归档的操作。单来源不可用时，其他来源仍可操作。搜索页保留查询、工作区、驱动和时间筛选、分页、重建状态与搜索结果跳转。跳转使用已有会话、轮次和条目身份。
3. 切换实例、关闭页面或插件停用时，注销对应订阅并处理在途请求，旧响应不会覆盖当前选择。验证两个实例并存时的页面区分和错误隔离。保留聊天、已有会话打开、浏览器和文件预览的现有入口行为。
4. 负责 Web 入口、插件工作页及必要的前端注册。后端契约由对应开发人维护。将默认组合需要挂载的页面和导航 ID 交 B1-06。整体布局、聊天迁移和审批改造留在后续批次。

## 自测与交付

- 跑现有 Web 平级插件和会话浏览回归，补有针对性的实例切换、失效状态和迟到响应测试。运行 `pnpm --filter @harnessmate/web typecheck` 和差异检查。
- 实际操作一次历史发现、预览、取消、导入和打开已有会话。实际切换两个搜索实例，测试中文查询、无结果、停用后恢复，并点开结果核对会话和轮次。记录使用的是夹具、源码运行环境还是候选包。
- 交付基线、任务提交或 PR、页面注册及导航 ID、使用真实插件联调的步骤、实跑结果、必要截图和待联调项。由总指挥对候选包独立验收。
