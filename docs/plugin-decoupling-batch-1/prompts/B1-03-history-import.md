# 开发提示词 · B1-03 导入与会话事务

你是 HarnessMate Desktop 第一批解耦的会话与导入开发人。请**实现导入插件、会话数据适配和旧 API 适配器**，保留历史数据与回放。总指挥负责接口裁定、独立验收和合并结论。 [任务单](../../plugin-decoupling-batch-1-tasks.md)

## 开工

在 `D:\HarnessMate\harnessmate_desktop` 相关开发目录核对 `git status -sb`、HEAD 和共同基线，保留用户与其他任务改动。先对齐 B1-01 的 DTO 和错误语义，与 B1-02 确认稳定来源身份，与 B1-04 确认快照、已提交变更和续读边界。来源实现尚未可用时用已确认契约的夹具开发。临时文件和数据副本放 D 盘。

先读 [会话浏览服务](../../../packages/daemon/src/core/session-explorer-service.ts)、[会话管理器](../../../packages/daemon/src/core/session-manager.ts)、[SQLite 存储](../../../packages/daemon/src/db/sqlite.ts) 和 [现有路由](../../../packages/daemon/src/server/app.ts)，梳理原生导入和归档包导入的实际语义。

## 实现要求

1. 通过 `history.import.v1` 提供来源选择、预览、目标工作区和提交。固定使用用户选中的来源引用读取。响应区分新建和复用，并给出稳定的会话 ID。接入原生历史和归档包两条既有路径。
2. 复用现有 `importSession` 及可复用的归档逻辑。原生导入在一个事务边界内检查去重、写入会话和原生映射、保存回放记录。能兼容匹配既有 `native_history_imports`。独立来源发生相同 native ID 时仍可分别导入。并发、重试和提交成功后响应丢失的情况要复用同一个会话。读取阶段支持取消，提交阶段以持久化结果为准。归档包沿用其既有重复导入和数据身份语义。
3. 由当前会话数据层统一写入，把提交后的变更及可衔接的快照和续读位置交给 B1-04。按实际持久化能力确定最小改动，覆盖新增、更新和删除。停用导入后已归档会话可继续打开、回放、搜索和导出。迁移保留旧工作区和会话身份。
4. 提供 `/api/v1/harnesses/discovered-sessions`、`/api/v1/harnesses/import-session`、`/api/v1/sessions/import-bundle` 的兼容适配，保持原请求、响应、导入模式及现有本机限制。B1-06 统一挂载 `server/app.ts`。分叉、Side Chat、回放和会话管理由现有业务路径继续提供。

## 自测与交付

- 对照旧 API 和插件入口的导入结果。用旧版数据副本、旧归档包、并发调用、取消、失败重试和提交后断线复现事务边界。检查会话 ID、映射数、事件数和可回放性。验证停用与恢复后已归档会话可读。
- 运行适用的 daemon 回归、类型检查和差异检查。说明数据库迁移、原数据所有权、配置或版本回退下的可读性。用脱敏副本记录证据。
- 交付基线、任务提交或 PR、实际契约与示例、旧路由到插件实例的映射、事务测试清单、实际命令结果与复验步骤。把已提交变更读取的用法交 B1-04，把待挂载路由交 B1-06。
