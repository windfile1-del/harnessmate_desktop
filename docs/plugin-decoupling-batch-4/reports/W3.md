## 2. 性能剖析（Baseline Profile）与根因定位

在任何代码修改前，先对合入完整 W2 后的候选在同机 Electron 35.7.5（`--disable-gpu`）上执行了 V8 CPU + Heap + LongTask + RPC 全链路剖析，原始轨迹保留在 `D:/HarnessMate/b4-tmp/w3/profiles/baseline/`（`profile-summary.json`、`chat.cpuprofile`、`shell.cpuprofile`）。

### 2.1 基线（W2 合并后）实测瓶颈
1. **>500ms 可见停顿（基线 1,408ms / 长任务 1,073ms；B3 524/606/756ms）**：
   - `ChatStage.tsx` 将进行中轮次内已完成的所有 `assistant_text` 块都压住为纯文本，直到 `turn.completed` 时一次性同步挂载 60 个 `<MarkdownView>` 并执行同步 `rehypeHighlight`（覆盖 190+ 语言全集），导致单帧 400–1,073ms 主线程冻结。
   - `studio-timeline`（`hm.plugin.message-studio/ui/panel.js`）在流式期间以 ~12Hz 调用 `replaceChildren()` 重建 2,501 个 `<button>` 节点，占聊天 isolate **77.3% CPU**。
2. **总 V8 堆显著超预算（B3 35.49MB / +61.75%；W2 基线 53.25MB，GC 后 43.24MB；预算上限 24.13MB）**：
   - 运行时同时存在 **5 个独立 V8 isolate**（Shell 15.98MB + 4 个 `about:srcdoc` iframe 共 37.27MB），重复装载 React、Zustand、Markdown/highlight.js 及 `PluginSlotSync` 壳层面板代码。即使只有 Shell + Chat 两个 isolate（B3 形态），双 isolate 固定堆开销也已达 35.5MB，客观证明仅靠微调 iframe 内代码无法落回 ≤24.13MB 预算，满足引入通用可信前端模块挂载选项的先决条件。
   - `transport.ts` 逐帧执行 `existing.concat(ready)`（O(N²) 全数组复制）以及 `projector.ts` 每帧对历史已完成块执行 `turn.blocks.map(b => ({ ...b }))`，在 60 秒 1,300+ 帧内制造数十 MB 旧生代短命垃圾。
3. **历史加载回归（B3 1,654ms / +41.01%；W2 基线 3,276ms；预算上限 1,290.3ms）**：
   - 串行拉取 13 页共 12,501 条事件（10,000 条对话事件 + 2,501 条尾部 `task.state_updated` 账本事件）。
   - 会话切换时 `BoundSessionSurface` key 含 `session.id` 触发整页卸载重建；启动期 `hm:shell:state` 反复触发未就绪 provider 比较导致 `readViewState` 重复调用 5–7 次。
4. **非目标会话的后台冗余贡献调用**：
   - `hm.plugin.agy-workbench-default` 在非 AGY 会话上仍挂载于 `composer.actions` / `session.sidebar.badge`，60 秒内发出 **941 次 `agy.workbench.v1.readWorkbenchState`**。
   - `hm.plugin.requests-view-default` 在无待处理请求时持续每 2 秒轮询，60 秒内发出 228 次 `snapshot`/`getMode` HTTP 请求。

## 3. 实施优化与架构改动

### 3.1 跨进程五点校准遥测与按需诊断
- 新增 `packages/daemon/src/core/perf-diagnostics.ts`、`packages/web/src/lib/perf-diagnostics.ts` 与环回诊断端点 `GET/POST /api/v1/diagnostics/perf`。
- **按需启用、零逐 token 落盘日志**：默认仅维护 O(1) 轻量原子计数；开启诊断后在内存环形缓冲记录五点边界：
  1. `runtimeReceivedAt`（`session-runtime-default` 接收驱动事件时间）
  2. `committedAt`（`session-data-default` 在 `txAccess.runImmediate` 返回后的**严格事务提交后时间**，显式区分 `event.createdAt`）
  3. `serverFlushedAt` 与 `hostWsReceivedAt`（`ws.ts` 刷新与 `DaemonWsClient` 接收）
  4. `pluginReceivedAt`（插件实际收到批次时间）
  5. `domRafRenderedAt`（MutationObserver + 2×rAF 可见更新时间，显式标注不等于 OS 合成器最终呈现时间）
- 通过 `/api/v1/diagnostics/perf` RTT/2 中点偏移校准 daemon↔renderer 跨进程时钟差（`clockOffsetMs`、`clockRttMs`）。
- 实测并暴露 `wsService`、`runtimeCommit`、`deltaCoalescer` 及前端插件队列的当前深度、高水位、最大积压时长、批大小 P95/最大值、活跃订阅数与活跃定时器数。

### 3.2 快照边界尾部历史分页与实时流衔接
- `packages/daemon/src/db/sqlite.ts` 新增 `getEventsBefore(..., minTurnEvents)` 与 `hasEventsBefore(...)`，走 `(session_id, seq)` 索引倒序定位最近轮次窗口（覆盖尾部连续非轮次元数据事件如 `task.state_updated`），返回严格连续的 `[earliestSeq..boundary]` 切片。
- `packages/plugin-api/src/session-contracts.ts` 与 `packages/daemon/src/plugins/session-data-default/index.ts` 扩展 `listEvents` 支持 `beforeSeq`、`tail`、`minTurnEvents`、`earliestSeq`、`hasEarlier`。
- `packages/web/src/plugins/chat-default/transport.ts` 首次加载仅按快照边界 `boundary` 拉取尾部窗口（1 次 `listEvents` 替代 13 次），与实时流 `> boundary` 无缝去重衔接；向上翻页通过 `loadEarlierHistory` 按 `beforeSeq` 前插，不丢事件、不重复显示、保留滚动锚点。

### 3.3 结构共享、画面周期批更新与流式高亮
- `transport.ts` 采用 **256 事件不可变分块**（`eventChunksBySession`）+ `createChunkedSessionEventProjector()`，每帧仅复制 ≤256 项尾块，消除 O(N²) 全数组复制。
- `projector.ts` 为每个 `TurnBlock`、`ProjectedToolCall`、`ApprovalRequest` 引入脏标记与 `WeakMap` 快照缓存，已完成块保持稳定对象引用供 `React.memo` 跳过重绘。
- `transport.ts` 使用 RAF + 24ms 兜底定时器按画面周期合并实时批，草稿写入 350ms 防抖且清空时立即刷盘（不丢最后 delta、不暂停后台会话、不自动发送草稿）。
- `MarkdownView.tsx` 从全量 `highlight.js` 改为 `highlight.js/lib/core`（18 种常用语言，chunk 从 173kB 降至 91kB），移除同步 `rehypeHighlight`，改用 512 项 LRU 缓存 + 5ms 时间片异步高亮队列与围栏代码块分块；`ChatStage.tsx` 按 `block.streaming` 逐块渐进渲染，消除 `turn.completed` 瞬时冻结。
- `hm.plugin.message-studio` 改为 80 项滑动窗口与增量 DOM diff；`ChatStage.tsx` 引入 `programmaticScrollRef` 避免自动滚动触发 `writeViewState` 风暴。

### 3.4 通用可信前端模块挂载选项与按需贡献清理
- `packages/plugin-api/src/slots.ts` 新增可选 `module`、`mountMode`（`'auto' | 'iframe'`）与 `when: { harnessKinds }` 声明。
- 新增 `packages/web/src/slots/shared-runtime.ts`（冻结暴露 `react`/`react-dom`/`zustand`，**不暴露宿主私有 `useAppStore`**）与 `packages/web/src/slots/TrustedPluginModuleHost.tsx`（与 `SandboxedPluginFrame` 共用同一套公开桥 API 与 `executeSandboxedBridgeMethod`，内置 `ModuleErrorBoundary`、卸载撤销全量清理、`services.subscribe` 契约自动解析）。
- **外部插件平权与可回退**：外部可信插件可使用完全相同的 `module` 入口与共享依赖；未声明 `module`、`mountMode: 'iframe'` 或设置 `localStorage.hm_force_iframe_mount = '1'` 时完整保留沙箱 `iframe` 挂载。
- **边界声明**：进程内可信模块依赖 `ErrorBoundary`、卸载撤销与安全模式/重启恢复，**不声称**对任意恶意死循环具备操作系统级硬隔离。
- 新增 `packages/web/src/plugins/chat-default/ChatSlotSync.tsx` 与直接叶子导入，将壳层面板与 `AgyWorkbenchShell` 排除出聊天包；为 `hm.plugin.agy-workbench-default` 的会话级槽位添加 `when: { harnessKinds: ['agy'] }`，将非 AGY 会话的 `readWorkbenchState` 从 **941 次降至 0 次**；`requests-view-default` 仅在存在 pending 请求时开启 2 秒校正定时器。
