## 3. 唯一事实、CAS 与送达

`approvals` 保留旧 ID、类型、终态和兼容字段。新增表均由请求插件管理：

- `request_facts`：owner、workspace、原提供方/代次/连接、session/turn/nativeRequestId、请求版本、幂等键、截止时间、送达状态、策略实例/修订、展示关闭、native 展示信息与精确选项决策回执。
- `request_commits`：单调提交游标及 request/version，可通过 snapshot 校正漏事件。
- `request_delivery_attempts`：发送开始/结束和送达状态。不会持久化凭据或可重放的敏感回复载荷。
- `request_modes`、`request_mode_history`：当前模式回执与配置历史。
- `request_tool_results`：模型插件工具 succeeded/failed；与批准送达分开记录。

决策状态沿用 `pending → approved/denied/resolved/expired/cancelled`。`expectedVersion` 和 SQLite immediate transaction 内的 pending CAS 只接受一次决定。桌面、旧移动 REST、策略、native 入口和到期均经过该事实。原生数字/string 请求 ID 保留类型，幂等键还包含连接、代次与 occurrence。

送达单独经过 `pending → sending → acknowledged/unknown/unavailable`。acknowledged 表示原执行资源确认接收/写出；**不等于底层工具副作用已完成**。模型工具另记真实调用结果，AGY 工具结果由原生协议/工具证据确认。异常发生在可能写出后时记 unknown，禁止盲目重发。决策完成后崩溃于 pending 发送区间会变为 unavailable；崩溃于 sending 会变为 unknown。此设计不宣称副作用 exactly-once。

共享 SQLite 的决策、请求版本、提交记录、审批终态事件及会话 awaiting 投影同事务提交；提交后发布更新。pending 数查询请求事实对应的待处理审批行，没有另存业务计数。不同实例/视图以 request version 与提交游标重建，默认视图订阅服务并每两秒校正快照。请求恢复在提供服务前处理截止时间和断开的原连接，再校正 awaiting。独立数据库不被描述为共享事务；第三方数据提供方需消费版本事件并按自身事务构建投影，未将 B3 数据领域接管到请求插件。

原请求的回复通过原 owner 定位；修改工作区默认绑定不会将旧请求回复给新驱动。native 的 `requestId/requestVersion` 镜像来自统一事实；W1 receipt CAS 仅保护协议写入，不再是另一个业务决策入口。native 原始表不由 W2 重建。

## 4. 模式与真实执行方式

| 用户请求 | 默认策略 | 驱动/回执语义 |
| --- | --- | --- |
| manual | 普通请求交用户 | 只在实际确认后显示驱动已生效；问题、凭据维持输入类型 |
| accept_edits | 低风险编辑及只读工具可允许，其他交用户 | 仅映射真实公布的 accept-edits/驱动能力；仍核对每个请求支持选项 |
| auto | 策略允许且驱动有对应 once 选项时自动回复普通工具 | native 没有 auto 模式、但有逐次权限回复时，使用默认模式 + 所选策略逐次处理，显示 policy_handled/per_request_policy |
| plan | 只读请求允许，写入/执行请求拒绝 | 驱动支持 plan 才声称 native plan；拒绝/不支持/新会话延后如实记录 |

`requested → policyInstanceId/policyRevision → driverRequested → driverAccepted → decisionReceipt → delivery/execution` 可查询。策略修订采用实际服务运行修订/runId，旧实现兼容路径仍走 evaluateToolCall。保存配置、运行中保存配置、驱动 updateConfig 未返回回执均不会自动标为 applied。

模式状态区分 `applied`、`pending_next_session`、`unsupported`、`rejected` 和 `policy_handled`；执行方式区分 driver/per_request_policy/none。启动前先记等待，驱动 `config.confirmed` 或明确接受回执到达后才更新。旧句柄的接受事件按该句柄真正请求的模式记录，不能直接套用后来保存的偏好。

`allow_session` 仅映射到驱动明确标注 session 范围的选项。原生 allow_always 不自动解释为 session；精确选项 ID、outcome、once/session/persistent/unknown 范围另存 `decisionReceipt`。无法用旧审批枚举表达的原生范围保持旧 decision 为 null，防止伪称 once 或 session。普通工具的自动允许不会填写 questionAnswer 或 secretValue。

默认规则、超时、风险复核均在插件配置中：请求实例 `timeoutMs/builtinRiskRules/annotatorTimeoutMs`，策略实例 `reviewHighRisk/deniedTools`。可信插件文件/网络/进程访问继续走原信任机制，没有新增逐项授权弹窗。

## 5. 到期、资源、关闭与停用

- 到期终态 expired；轮次结束、连接失效、策略/请求提供方停止为 cancelled，保留原因。取消计时器，更新 pending 和 awaiting，按原连接能力发送 deny/cancel。连接已失效时结束事实并释放回调，不给新连接重放。
- 重启不重建旧执行回调：先检查截止时间，过期标 expired，尚未到期但原连接丢失标 cancelled。已有终态、unknown 和关闭状态保留。
- 问题和凭据有独立表单与状态；凭据只短暂进入执行资源，完成后清理。不会写普通 KV、事件、审批输入、日志、回执或导出。
- UI 的 pending 只来自服务快照，历史事件不能复活卡片；终态移至历史，“关闭”按 requestId 存储且不删除事实。关闭后重启仍隐藏。
- UI 停用只释放 UI 订阅/轮询。策略停止终结其固定归属的 pending；请求提供方停止终结自身在途。没有宿主补建或自动选择其他提供方。模型工具租约释放也终结所属代次的在途请求。

## 6. 界面及旧入口

默认聊天通过 `BoundSessionSurface` 挂载 `runtime.requests.view.v1` 的 `requests-queue`。`ApprovalCenter`、native 队列/卡片/表单、规则 modal、全局跨会话队列与相关可写 store 已迁入请求视图。宿主/聊天中的 pendingApprovals store 及 resolve/refresh 实现已删除。聊天历史 projector 只保留历史事件的兼容读取，不用于待处理队列。

AGY 工作台保留归属及协议收据的只读引用，提示在绑定请求视图处理；没有备用操作按钮或审批提交逻辑。AGY 构建守卫禁止打包请求业务实现；请求视图构建守卫禁止打包宿主 app-store。仅停请求 UI 不会暴露 AGY 的备用批准入口。

| 兼容入口 | 现在的处理 |
| --- | --- |
| GET `/api/v1/approvals`、会话详情 pendingApprovals、旧 WS attention | 从请求实例事实读取/转发，保留移动端协议 |
| POST `/api/v1/approvals/:id/resolve` | 转到原 owner 的同一版本/CAS；重复或迟到返回 409 |
| POST `/api/v1/approvals/:id/close` | 按原 owner 持久化展示关闭；pending 不允许关闭 |
| GET `/api/v1/sessions/:id/request-mode` | 当前真实模式回执 |
| `/api/v1/approval-center/*` | 默认请求插件的规则与历史兼容门面 |
| native requests/resolve、AGY runtime resolveRequest | native 先验证选项/代次，然后进入统一请求 CAS，再写原协议连接 |

W1 `legacyApprovalBridge` 元数据现在声明 unified_requests；旧 DTO 字段/兼容方法可继续读，临时镜像审批写入和驱动本地自动策略已删除。账号契约和原协议执行账本仍由 W1 所有。

## 7. 数据迁移与回退边界

迁移幂等收编旧 approvals 行为 request_facts，ID 和终态不变；旧 pending 不跨连接恢复。旧规则实例 ID/KV 保留。新增表/列采用附加方式，不删除旧事件与审批字段。native 原始协议、账号以及 B3 数据/运行/聊天表所有权不变。

迁移逻辑与重启行为在本域 SQLite 测试及浏览器重启中验证。没有执行真实 B3 EXE 的降级读回验收；本批成品级 B4-A7 回退矩阵由 W3 在隔离数据副本上完成。关闭状态属于新表，旧 B3 UI 不理解该展示字段，不能承诺旧 EXE 隐藏相同卡片。

## 9. W3 消费与合入

W3 从本分支完整交付 SHA 合入，历史已包含 W1 D1/D2；无需再挑选 W1 提交。最终集成标准检查、真实账号条件、成品级迁移回退和 B3-A8 保持独立结论。

外部策略/视图样例：`plugins/examples/hm.plugin.request-policy-lite`、`hm.plugin.request-view-lite`。策略实例配置 `{decision:'allow'|'deny'|'ask',scope:'once'|'session'}`；通过既有安装和实例绑定入口选择，不导入 daemon 内部模块。最小视图不伪造问题/凭据/native 表单输入；完整体验使用默认视图或实现相同公共 DTO。

```ts
import type { RuntimeRequestsServiceV1, RequestDeliveryServiceV1 } from '@harnessmate/plugin-api';

// W3/外部视图：通过页面 bridge 调用，实例选择遵循已有 binding。

  'runtime.requests.v1', 'snapshot', [{ includeHistory: true }],
);
const fact = result.value.value.requests.find(r => r.status === 'pending');
if (fact) await window.harnessMate.services.call('runtime.requests.v1', 'resolve', [{
  requestId: fact.requestId, expectedVersion: fact.version,
  actor: 'desktop', decision: 'allow_once',
}]);
// 服务订阅通知后再读 snapshot；流重置/版本缺口直接重建，勿用历史 pending 事件复活卡片。
const unsubscribe = await window.harnessMate.services.subscribe(
  { contract: 'runtime.requests.v1' }, () => refreshSnapshot(),
);
```

外部执行方在自己的运行代次注册 `runtime.request-delivery.v1`，公开 create 的 `deliveryResource` 指向原实例/runId/resourceId；validate 检查原连接、选项与截止时间，deliver 返回实际送达结果，release 释放内存句柄。敏感输入只在该瞬时调用中传递。不同连接不复用 resourceId；重新连接不能认领旧请求或重发 unknown。默认 AGY 已通过其内部窄适配做相同原连接约束。
