# HarnessMate 平级插件架构与迁移计划

状态：已完成「下一阶段 · 统一装配并迁出浏览器与预览」（平级多实例服务目录、通用桌面视图内核、预装桌面/无头浏览器及文本/Markdown/审批策略插件、前后端绑定与空组合恢复），并通过单元测试与 Windows 便携版实机验收。「其余功能迁移」待按批次推进。

## 目标架构

**除内核外，所有功能由平级插件实现。** 随应用预装的插件和用户安装的插件使用同样的注册、依赖、生命周期和启停规则。预装组合是一份插件清单，用户可以在自己的组合中选用任意实现。

内核只负责启动与恢复、插件装配与生命周期，以及窗口、IPC、事件和存储等基础能力。信任记录与运行权限由内核执行。聊天、会话管理、历史导入、Harness 驱动、浏览器、文件预览、终端、账本、审批策略和插件中心界面都属于插件。安全模式由最小恢复界面提供停用、回退和恢复组合操作。

## 平级插件如何协作

- **能力可以并存。** 服务按「插件 ID、实例 ID、能力契约」注册。同一契约允许多个实例同时工作。界面、命令和路由按插件及实例归属，两个同类插件可以同时提供各自的入口。
- **依赖由调用方选择。** 需要调用另一插件时，调用方声明所需契约和版本。组合可以为各个插件实例、工作区或会话保存所选实现。会话使用明确绑定的实例，安装顺序和插件来源均无需参与选择。
- **生命周期归属插件实例。** 内核按实例跟踪页面、监听、服务、文件状态和托管进程。停用或回退一项插件时只回收该实例的贡献。使用该实例的调用方可按组合显式切换到另一个已启用实例，或显示依赖暂不可用。
- **运行授权与装配独立。** 各插件可以按用途采用相应运行方式。相同信任等级使用相同的系统能力和宿主接口。内核为托管资源分配身份与作用域。插件主动选用同一个固定端口、文件或第三方账户时，由资源自身的规则处理共享和占用。

例如，桌面浏览器插件和无头浏览器插件可以同时安装、运行并提供各自的工作页。会话可保存其中一个浏览器实例作为它的浏览器依赖，另一个会话可以使用另一实例。文件预览同理，文本和 Markdown 都以插件身份提供各自的查看器。

### 现行恢复操作

| 操作 | 用户入口 | 结果 |
| --- | --- | --- |
| 关闭一个功能扩展 | 插件中心的扩展点设置 | 当前扩展点恢复内置实现，插件的其他贡献继续可用。 |
| 停用或撤销一个插件的信任 | 插件中心的插件设置 | 立即停止接收新的调用，回收该插件的页面、监听、服务和托管进程。其接管的宿主能力恢复内置实现。 |
| 回退插件版本 | 插件中心现有「回退」入口 | 恢复已保存的上一版本。按当前信任记录和有效授权重新检查，再激活。 |
| 恢复扩展配置 | 插件中心的组合设置 | 恢复宿主管理的上一套可用扩展配置和服务绑定。插件包版本单独管理。 |
| 安全模式启动 | 托盘菜单、启动失败对话框或桌面启动参数 `--safe-mode` | 启动时采用内置组合，暂停用户插件和用户组合覆盖。保留插件文件和配置，进入应用后可检查、停用或回退，再正常启动。 |

新增扩展点默认选用内置实现。启用外部实现时，宿主先检查 API 兼容性、当前授权和提供方就绪状态，成功后才切换并保存配置。候选版本启动失败保留旧状态，已启用的实现崩溃、撤权或停用时恢复内置实现。对可安全重试的只读请求直接回落，含写入的在途调用先报告结果并避免自动重试。停用后以现有 `runId` 校验拒收旧实例的迟到结果。

回退的范围是插件包、宿主管理的绑定和配置。插件已经写入工作区或外部服务的数据由相应工具的数据恢复能力处理。首轮插件数据采用可兼容的存储格式，使上一版可重新读取。

#### 使用与开发

1. 在插件中心的「开发 / 脚手架」生成「Markdown 文件预览」并关联开发目录。也可以在生成时取消关联，然后到「安装 / 创建插件」安装生成的目录。CLI 脚手架使用 `pnpm create:plugin --id user.markdown-preview --name "Markdown 文件预览" --template markdown-preview`。
2. 在已安装插件的「权限」中为相应工作区授权 `file:preview`。进入「查看完整组合」，从「右侧文件预览」选择该插件。组合保存应用级的提供方选择，每个工作区仍单独授权。切换到「内置文本预览」会清除这一项绑定，插件的其他功能仍可用。
3. 通过聊天里的文件链接或侧栏文件列表打开 Markdown。插件返回的行号可以标出渲染块。内置预览按原始文件行号定位。插件权限撤销后，同一文件直接回到文本预览。回退插件版本时使用当前有效的授权，必要时从插件中心重新授权。

V4 清单使用 `contributes.filePreview.extensions` 声明类型，代码入口导出 `renderFilePreview(file)` 并将 `ui.filePreview.v1` 列为所需特性。输入是经过校验和截断的单个文件快照，包含工作区相对路径以及可选的源行号。输出支持版本 1 的 Markdown 或文本，输出的 `line` 对应转换后的内容。返回 `null` 使用原始文本。Markdown 支持格式化块和跳转到工作区文件，图片显示替代文字。公开类型见 [插件 API 报告](plugin-api/plugin-api.api.md)。

宿主保存选择到 `profile.json` 的 `extensions.filePreviewProvider`。备份与恢复包含这一项。渲染通过现有隔离进程 RPC 执行，调用有 600 毫秒超时。插件失败只影响此次预览。旧版本实例、已撤销授权和切换前的迟到结果会被丢弃。

## 后续迁移顺序

### 下一阶段 · 统一装配并迁出浏览器与预览

首批交付同时包含装配机制和两项现有功能迁移。优先跑通浏览器，再用文件预览验证同一种机制能复用。沿用当前 `PluginHost`、组合文件、版本快照和安全启动入口。

`PluginHost` 已维护依赖图，实际服务表仍以契约名作为唯一键。网页的主工作区默认挂载聊天组件，插件工作页经单独入口进入。浏览器由 Electron 专用桥接提供，文件预览则由 daemon 和右侧面板分别选择渲染路径。首批迁移将这些业务入口改为调用实例注册目录。 [服务表](../packages/daemon/src/plugin-host/runtime/lifecycle.ts) · [主工作区](../packages/web/src/App.tsx) · [浏览器桥接](../packages/electron/src/plugin-browser.ts) · [文件预览](../packages/web/src/components/InspectorDrawer.tsx)

#### 1. 同一套插件装配

- [x] 服务目录按插件 ID、实例 ID 和契约登记实现。同一契约下可以有多个提供方，一个插件也可以按不同配置运行多个实例。预装包、用户安装包和关联的开发目录都接入这套目录。
- [x] 实例声明自己的依赖，组合为具体调用方配置提供方。工作区和会话可以保存各自的选择。已有会话继续按保存的绑定调用，显式切换后才使用所选的新实例。依赖未就绪时，仅对应调用方进入等待状态。
- [x] 页面、侧栏入口、命令和本地路由由实例注册。内核提供通用桌面视图的创建、挂载、尺寸变化、焦点与销毁。插件决定视图内容和布局，也可以提供完整工作页。启动页和页面布局由组合中的插件提供。
- [x] 信任本地开发目录后，插件后端可直接使用 Node.js、本地进程、网络和文件系统。添加页面、路由或服务沿用这份信任。模型发起的工具调用经会话选定的审批策略插件处理，内核执行该决策。现有面向旧插件的运行方式纳入兼容层。

#### 2. 把现有功能搬进插件

| 顺序 | 迁移工作 | 交付条件 |

### 其余功能迁移

| 批次 | 功能 | 迁移重点 |
| --- | --- | --- |
| 工具和数据 | 历史导入、搜索、Git、终端、账本、用量、附件及 MCP 管理 | 将 API、后台任务、页面与数据访问一起归属插件。旧数据在迁移期间按原有 ID 读取。 |
| 会话和驱动 | 聊天、会话管理、Codex、Claude、AGY、ACP、审批、交接和调度 | 根据依赖逐批移出 daemon 启动路径。会话 ID、事件序号和已有驱动绑定可恢复。按会话实例验证中断、审批、恢复和多驱动并行。 |
| 应用界面与管理 | 工作区、侧栏、设置、插件中心、开发工具和远程访问 | 用预装组合装回默认体验。插件中心和开发界面与其他插件按同一机制管理，内核的恢复入口可以重建它们。 |

每项业务迁移的完成条件是默认功能通过插件提供，业务初始化由插件生命周期触发，同类插件可并存，已有数据能够读回，停用与回退通过打包验收。最终以空组合验证内核启动与恢复，再逐一启用插件装回现有功能。
