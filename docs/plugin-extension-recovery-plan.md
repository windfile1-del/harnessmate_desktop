# HarnessMate 插件扩展与回退开发方案

状态：P2 已接入可替换的右侧文件预览。它是第一个可独立关闭并恢复内置实现的宿主扩展点。

## 范围

沿用现有的 `PluginHost`、`profile.json`、`patch.yml`、插件包修订指针和 SDK。长期目标是让业务功能可以通过插件新增、调整或替换，应用核心负责装配、授权、数据兼容和恢复。每个功能独立迁移，保留当前实现作为默认实现。首轮的会话、数据库和三种 CLI 的执行入口继续使用现有路径。

首轮交付两个可独立验收的用例。一个插件在自己的工作页接入本地浏览器后端，另一个插件扩展右侧文件预览。两者安装完成后，修改插件功能只需编辑插件目录。

## 长期可替换范围

| 层 | 插件可以做什么 | 宿主负责什么 |
| --- | --- | --- |
| 应用界面 | 注册独立工作页，替换指定区域的预览器、聊天块、工具结果、侧栏内容和审批详情。 | 桌面窗口、页面载入、插件管理及恢复入口。 |
| 业务服务 | 提供自己的历史导入、索引、浏览器后端、账本、交接等实现，由用户在组合配置里选择默认提供方。 | 服务契约、依赖和生命周期、默认实现与切换恢复。 |
| 会话工作流 | 注册 Harness 驱动、命令和工具，逐步开放上下文处理、会话调度和审批界面的扩展。已开放的工作流可配置使用插件策略。 | 会话身份和有效状态、权限执行、事件提交和数据兼容。外部 CLI 内部逻辑由对应 CLI 或自定义驱动提供。 |
| 启动与恢复 | 通过稳定 SDK 注册和撤销贡献，读取宿主支持的功能、版本和运行状态。 | 桌面启动、安全模式、插件装卸与信任记录、权限校验、持久数据迁移和恢复。 |

插件权限包含两个独立的选择。**运行方式**决定插件能否直接使用操作系统能力。**扩展点绑定**决定插件能接管 HarnessMate 的哪些功能，由用户单独选择和撤销。可信本地进程用于故障隔离和资源回收。它以当前系统用户运行，受保护的核心指公开扩展接口中的边界。若要防止插件直接写入同一账户可写的宿主文件，还需通过操作系统权限隔离进程和数据。

功能可以按用途设计扩展方式。命令、工具和工作页通常允许多个插件同时新增。日志、格式转换和上下文处理可提供有序钩子。文件预览、导入器和调度策略等由配置选定一个实现。宿主内的消费代码通过相同的版本化接口调用内置和插件实现。内置代码可以原地保留，后续再按维护需要移动到独立模块。

## 恢复操作

| 操作 | 用户入口 | 结果 |
| --- | --- | --- |
| 关闭一个功能扩展 | 插件中心的扩展点设置 | 当前扩展点恢复内置实现，插件的其他贡献继续可用。 |
| 停用或撤销一个插件的信任 | 插件中心的插件设置 | 立即停止接收新的调用，回收该插件的页面、监听、服务和托管进程。其接管的宿主能力恢复内置实现。 |
| 回退插件版本 | 插件中心现有「回退」入口 | 恢复已保存的上一版本。按当前信任记录和有效授权重新检查，再激活。 |
| 恢复扩展配置 | 插件中心的组合设置 | 恢复宿主管理的上一套可用扩展配置和服务绑定。插件包版本单独管理。 |
| 安全模式启动 | 托盘菜单、启动失败对话框或桌面启动参数 `--safe-mode` | 启动时采用内置组合，暂停用户插件和用户组合覆盖。保留插件文件和配置，进入应用后可检查、停用或回退，再正常启动。 |

新增扩展点默认选用内置实现。启用外部实现时，宿主先检查 API 兼容性、当前授权和提供方就绪状态，成功后才切换并保存配置。候选版本启动失败保留旧状态，已启用的实现崩溃、撤权或停用时恢复内置实现。对可安全重试的只读请求直接回落，含写入的在途调用先报告结果并避免自动重试。停用后以现有 `runId` 校验拒收旧实例的迟到结果。

回退的范围是插件包、宿主管理的绑定和配置。插件已经写入工作区或外部服务的数据由相应工具的数据恢复能力处理。首轮插件数据采用可兼容的存储格式，使上一版可重新读取。

## 开发顺序

### P0 · 接通关闭与恢复

- [x] Electron 和 daemon 支持安全模式。托盘可切换启动模式，启动失败时可进入安全模式。已运行的 daemon 只有在版本和模式都匹配时才会复用。
- [x] 插件中心提供恢复上一套配置和恢复内置组合。受管配置保存前会记录已解析的 `profile.json` 和 `patch.yml`，正常启动可继续未完成的恢复操作。自定义组合包文件独立管理，组合包丢失时仍可恢复内置组合。
- [x] 安全模式可检查第三方插件、回退保存的版本，并在组合配置可用时安排下次启动停用。常规模式在回退候选启动成功后才更新版本指针。安全模式保存的回退在下次正常启动时加载。
- [x] 把「单个扩展点恢复默认」接入右侧文件预览。
- **出口条件**。即使 `patch.yml` 无法解析、插件启动即崩溃，用户仍能进入应用并继续使用内置功能。

本轮验证通过了三条新增回归用例。它们覆盖损坏组合下暂停外部插件并恢复配置、启动时继续未完成的恢复、回退候选无法启动时保留当前版本。另用构建后的 daemon 验证了 `--safe-mode` 能启动并提供应用页面，以及恢复内置组合的 HTTP 操作。托盘切换和启动失败对话框留待成品验收。

全量测试中的 OpenCode Windows 进程回收用例在修改前的源码上也超时。AGY 认证预检用例仍出现 Windows 临时目录清理 `EPERM`。其余失败用例在仓库外的 D 盘临时目录复跑通过。

### P1 · 可信本地服务与插件工作页

- [x] 开发页提供「关联并信任」和「撤销信任」。信任绑定插件 ID 与规范化的源码路径，后续编辑沿用信任，切换目录需重新确认。可信本地进程复用 RPC、日志、超时和销毁机制。普通插件继续使用现有沙箱，安全模式暂停用户插件。
- [x] 增加 `workspace.pages`，从应用侧栏进入主工作区。后端在 `apply` 中启动并报告就绪，在 `ctx.effect` 中登记清理。页面通过 `onMessage` 与当前实例通信，进程停用后回收待处理调用。浏览器示例复用桌面 HTTP(S) 预览，关闭页面时回收预览实例。
- [x] 插件开发模式与 SDK 提供浏览器工作页脚手架。开发目录单独保留当前和上一份运行副本，保存后尝试启动候选，失败时恢复原版本。手动回退、重启、停用和撤权都走受管生命周期，源码目录保留用户当前编辑。可信后端可以直接使用系统权限，宿主桥和模型工具使用独立授权。 [浏览器工作页使用说明](plugin-browser-preview.md#带本地后端的浏览器工作页)
- **出口条件**。在 HarnessMate 内生成浏览器工作页示例，只改插件目录即可换后端或界面。验证中文输入、热重载、停用后进程与页面回收、上一版恢复和重启后的状态。

Windows Electron 验收覆盖脚手架生成、可信运行确认、浏览器授权、侧栏打开工作页、离屏画面和中文输入。修改查看器源码后，旧 HTTP 服务关闭，工作页载入新版本。从插件中心回退可以重新打开上一版。停用后工作页入口、离屏预览和服务均已回收。验收使用独立的 D 盘数据目录、软件渲染和 Chromium 沙箱。

自动化回归覆盖候选启动失败后恢复上个运行副本、保留源码编辑、已停用实例的服务不可达、安全模式暂停可信实例、正常重启读回快照，以及撤销信任后的权限与进程状态。插件契约、构建、类型检查及 Web 测试通过。daemon 全量回归仍遇到原有的 OpenCode 进程回收超时和 AGY 认证预检临时目录清理 `EPERM`。

### P2 · 验证一个可替换的宿主扩展点

- [x] 在右侧文件预览的渲染入口增加一个可选提供方。复用原有工作区路径校验、读取接口和行号定位，内置文本预览作为默认实现。提供方只接管自己声明支持的文件类型。
- [x] 交付「Markdown 文件预览」脚手架。渲染出错、超时、停用或撤权时，当前面板恢复内置预览并保留路径与行号。
- [x] 用打包后的 Windows 应用分别验收默认路径、扩展路径和失败恢复。运行公共 SDK、会话和三种 CLI 的回归用例。
- **出口条件**。内置文件预览无需改配置即可工作。用户可以单独关闭 Markdown 预览贡献、单独停用插件或回退版本，关闭后聊天文件链接仍打开右侧预览。 [文件预览入口](../packages/web/src/components/InspectorDrawer.tsx) · [守护进程读取入口](../packages/daemon/src/server/app.ts)

#### 使用与开发

1. 在插件中心的「开发 / 脚手架」生成「Markdown 文件预览」并关联开发目录。也可以在生成时取消关联，然后到「安装 / 创建插件」安装生成的目录。CLI 脚手架使用 `pnpm create:plugin --id user.markdown-preview --name "Markdown 文件预览" --template markdown-preview`。
2. 在已安装插件的「权限」中为相应工作区授权 `file:preview`。进入「查看完整组合」，从「右侧文件预览」选择该插件。组合保存应用级的提供方选择，每个工作区仍单独授权。切换到「内置文本预览」会清除这一项绑定，插件的其他功能仍可用。
3. 通过聊天里的文件链接或侧栏文件列表打开 Markdown。插件返回的行号可以标出渲染块。内置预览按原始文件行号定位。插件权限撤销后，同一文件直接回到文本预览。回退插件版本时使用当前有效的授权，必要时从插件中心重新授权。

V4 清单使用 `contributes.filePreview.extensions` 声明类型，代码入口导出 `renderFilePreview(file)` 并将 `ui.filePreview.v1` 列为所需特性。输入是经过校验和截断的单个文件快照，包含工作区相对路径以及可选的源行号。输出支持版本 1 的 Markdown 或文本，输出的 `line` 对应转换后的内容。返回 `null` 使用原始文本。Markdown 支持格式化块和跳转到工作区文件，图片显示替代文字。公开类型见 [插件 API 报告](plugin-api/plugin-api.api.md)。

宿主保存选择到 `profile.json` 的 `extensions.filePreviewProvider`。备份与恢复包含这一项。渲染通过现有隔离进程 RPC 执行，调用有 600 毫秒超时。插件失败只影响此次预览。旧版本实例、已撤销授权和切换前的迟到结果会被丢弃。

#### P2 验收

- Windows 0.6.0 x64 便携版使用隔离数据目录和模拟聊天记录验收。相对链接和 Windows 文件 URI 均在右侧打开并滚动到第 42 行。组合页可以切换到 Markdown 或单独恢复文本。停用、撤权、版本回退、抛错和超时均保留文件与行号。Markdown 中指向其他工作区文件的相对链接也能打开右侧预览。
- daemon 回归覆盖未授权工作区、大小写后缀、工作区外路径、损坏候选版本、超时、异常退出、无效输出、权限变更期间的迟到结果，以及正常和安全模式重启。SDK 契约、构建与类型检查通过。
- 全量回归中 Web 125 项、协议 6 项和 daemon 265 项通过，含 Codex 与 Claude 适配器、AGY 协议回放及跨 Harness 会话测试。daemon 另外两项复现 P1 记录的 Windows 问题，即 OpenCode 进程回收超时和 AGY 认证预检用例清理临时目录时的 `EPERM`。CLI 回归采用测试夹具和离线回放。
- 工作区内的 electron-builder 在 pnpm 依赖扫描时遇到 SQLite 错误。验收包使用相同的编译输出、Electron 分发和打包配置，在 D 盘独立目录执行 electron-builder。验收包未签名。

## 今后新增宿主扩展点

每个需求只改它所在的宿主入口。先把当前实现接到小接口上，再加入插件实现和配置选择。提交时一起交付默认实现、独立开关、接口版本、出错恢复和回归验证。若替换涉及运行中的会话，选择可安全切换的时点，必要时标记为下次启动生效。

首批交付本地服务、工作页、恢复路径和文件预览验证。文件预览通过后，下一批建议挑一个后台服务验证相同模式，例如会话历史导入。再按实际需求开放聊天区域和会话策略。涉及共享会话状态、审批和数据持久化的接口，随各自的功能需求独立设计与验收。

在插件中心的能力目录里标出每个功能当前支持的扩展方式、可选实现和恢复入口。一个功能只有在第三方实现能接管、停用后正常回到内置实现、失败后会话和数据仍可用时，才标记为可替换。用这份目录跟踪解耦范围。
