## 3. 内核与插件的职责

| 内核保留 | 普通插件拥有 |
| --- | --- |
| 启动、组合、安装修订、信任、依赖、实例与运行代次、恢复入口 | AGY 协议适配、账号/profile、认证流程、原生运行与工作流、命令、模型、Skills、工作台 |
| 通用服务/路由/订阅/进程/视图/存储事务，资源撤销 | 请求队列、审批记录、策略、规则/风险注解、会话授权、到期处理、用户问题、凭据交互、审批 UI |
| 核对资源所属实例/代次，按目标实例转发执行 | 厂商/账号来源策略、模式解释、native 权限选项、实际 CLI 回执与错误转换 |
| 最小恢复和诊断界面 | 历史投影、流式调度、消息渲染、性能优化及业务界面 |

权限划分继续保持清楚：可信插件的 Node.js、文件、网络和本地进程访问沿用既有信任；模型工具请求由选定策略处理；CLI 是否接受模式/选项以其协议回执为准。不能把三者混为同一组新增权限弹窗。

厂商类别不是内核特权。AGY 现有账号来源/provenance 产品规则迁入默认 AGY 插件及其配置，保留旧组合行为；内核只核对真实调用身份和资源代次，不承担厂商白名单。替代插件可以提供自己的业务策略。外部系统尚未接受的配置不能显示为已生效。

同类插件可以并存。对同一请求、句柄和存储资源的操作需要明确持有者，这是避免重复回复和串号的业务规则，不是同类插件全局互斥。

### 5.1 身份与运行中的请求

- 区分插件包、插件实例、插件 runId、harnessId、AGY profile/账号、native runtimeId/generation、sessionId/turnId、nativeRequestId 和业务 requestId。
- 旧 AGY profile 的 `instanceId` 不能直接当作新插件实例 ID。保留旧字段兼容含义，通过明确映射补充 `driverProviderInstanceId` 等提供方身份。
- 命令、请求和结算在创建时固定所属实例/代次；修改工作区默认绑定只影响后续操作，不把在途回复发到新连接。
- 快照/事件带提供方、流身份与游标。跨实例切换不能沿用另一数据流的 seq。
- 进程内旧 `onTimeoutDeny`、settlement sink 等回调由所属插件内部适配，跨插件只交换可序列化资源引用和回执。通用消息基础设施不识别 AGY 专用函数。

### 5.2 W1 与 W2 的交接

W1 先保留可运行的旧审批窄适配，提供请求注册/回复端点、native 选项、绑定修订、截止时间和结算协作示例。W2 再接管通用请求生命周期，并删除该临时旧业务路径。

AGY 原始协议、连接和 native 执行记录归 W1；统一请求状态、决策、到期和 UI 事实归 W2。两个域不得同时为同一请求维护独立可写审批真相。native 只读镜像带来源和版本，由请求事实更新。共享连接可事务提交；独立存储使用明确 outbox/回执恢复协议，不宣称跨两个数据库自动原子。

## 6. B4-W1：AGY 原生功能组

### 6.1 账号、驱动与加载

1. 将 `core.harness.agy` 的 adapter factory、profile 配置、默认账号与多账号注册迁到普通插件。沿用 B3 provider 目录和 binding，不再创建全局单例 AGY 服务。
2. 同步删除 registry、隔离 manager、runner 中的 `agy` 类别保留分支；同名类别按插件实例区分。更新相关公开契约和生成快照，不以改一个报错代替整条接线。
3. 迁移 `AgyAuthService`、profile manager、launch/config scope、生态发现和账号 API。一个包的两个实例能使用不同 CLI、home 和账号目录，登录/注销只影响明确目标。
4. 默认组合通过数据提供旧 `agy`/profile 别名，沿用旧 harnessId/nativeSessionId。认证不额外制造一套插件权限；状态、CLI 生效回执与配置版本可查询。

### 6.2 Native 领域与生命周期

5. 插件创建并持有 `AgyNativeRuntimeRegistry`、`wireAgyNativeRuntime`、连接、订阅、persistence、provenance 和 held settlement。`app.ts` 不直接 import/构造 native 业务对象。
6. 原生运行、子代理、swarm、boost、teamwork、dynamic workflow、Goal/schedule tasks、命令/模式/模型/effort、artifact/plan/diff/browser、生态配置及恢复全部保留；可按共同生命周期组成若干插件，不要求每个按钮独立成包。
7. `NativeRuntimePort` 消费端改为公开契约的窄客户端，不持有 native 内部类或厂商 `instanceof` 分支。真实厂商校验和 native 控制放到对应插件内部。
8. 原命令 idempotency、expectedRevision/CAS、binding generation、effect outbox、held settlement 语义沿用。重连/取消/旧回复不造成重复命令或双重结算。
9. lifecycle 清理包含 native 定时器、认证交互、观察器、连接和子任务资源。仅停工作台不停止后台轮次；停实际运行提供方时停止接单并记录可恢复或已中断结果。某账号实例停止不影响另一个账号。

### 6.3 工作台与兼容路由

10. 将 AGY 工作台注册、业务 store/native-client、Composer 相关控件与 artifact 业务视图归到插件前端。默认聊天通过通用贡献挂载选定提供方，取消宿主按 `harnessKind === 'agy'` 创建业务视图的路径。
11. 只补现有页面贡献缺少的通用内嵌区域能力，不启动第五批布局重写。默认与外部提供方使用相同挂载机制，外部插件不导入宿主私有 Zustand。
12. 保留旧 AGY URL、DTO 和 WS 行为，由兼容适配定位原持有实例；运行和账号路由的业务处理在插件内。停用后明确不可用，无宿主默认 AGY 回落。

### 6.4 完成条件和交付

- 默认 AGY 从新建/旧会话恢复到发送、native 更新、取消、重连、终态结算工作，保持原 ID。
- 两个工作区绑定不同 AGY 提供方；同包两个账号实例同时工作，注册顺序不改变选择。
- 外部 `agy-driver-lite` / 工作台样例只依赖公开 SDK，能完成真实产品注册/绑定、协议回放、命令和取消；无需实现默认包的所有可选工作流，但声明的能力必须可用。
- 每类既有 native 工作流至少有可运行回放与前端消费样例，所有权、启停与数据连续性明确；真实 CLI/账号的可用条件及结果单列。
- 输出 `reports/W1.md`，含契约、账号/旧 ID 映射、所有权表、旧路由映射、W2 请求/回复示例、临时兼容项及完整交付 SHA。

## 7. B4-W2：请求、审批与真实权限模式

### 7.1 请求领域拥有业务真相

1. 合入完整 W1 后，将审批创建、持久化、规则、计时、恢复、回复、注解与回执迁到普通请求插件。移除 `SessionManager` 的 `approvalTimers`、`fallbackApprovalCenter` 及构造/恢复中的业务写入。
2. CLI、AGY native 和模型插件工具使用同一个请求服务/策略入口。原生选项、用户问题和凭据请求保留类型，不把所有请求一律变成可自动批准的工具调用。
3. 每个请求保存原提供方、驱动代次、session/turn/native request、截止时间、请求版本及幂等键。沿用旧审批 ID/终态枚举，新增字段兼容读取。
4. 决策状态与送达状态分开：使用 CAS 接受唯一决策，再由 outbox/执行回执记录待发送、已确认或结果不明。桌面/移动/策略同时回答只接受一次；有副作用但回执不明时不能宣称 exactly-once，也不能盲目重发。
5. pending 数与会话 awaiting 状态由请求事实驱动更新。共享存储可用同一事务；跨插件以提交后事件、版本和可重建投影衔接，确保崩溃后可校正，不能保留两套独立计数器。

### 7.2 权限模式和策略的执行链

6. 统一记录并展示：用户请求模式 → 选定策略及修订 → 发给 CLI 的参数/协议请求 → CLI 接受的模式 → 请求决策 → 驱动回复回执。
7. `manual/accept_edits/auto/plan` 的默认规则放默认策略插件。底层能力不支持时，显示不支持、等待新会话或策略侧处理；仅保存配置不等于已生效。
8. 自动模式允许的普通工具请求，在策略允许且 native 选项支持时直接回复，不反复要求用户点击。native 不提供自动模式但提供逐次回复时，可由用户选定的策略执行逐次自动决策，并清楚标注实际执行方式。
9. Plan 行为按已选驱动能力和策略执行；`allow_session` 只能映射驱动实际支持的范围/选项。普通工具自动批准不用于自动填写用户问题或凭据，也不虚构未知子代理归属。
10. 已有 `approval.policy.v1` 的模型工具消费者和本机/隔离实现使用兼容路径。默认规则、风险分级、注解超时为插件配置，不能变成所有替代策略不可更改的内核规则。

### 7.3 到期、关闭和恢复

11. 请求到期、轮次结束、连接失效和实例停止分别进入对应终态；原计时器取消，待处理集合/计数更新，拒绝或取消回执按驱动能力发送。
12. 重启先处理持久化 pending 的截止时间，再发布待处理快照。若旧连接不再有效，只结束旧记录，不能把旧 nativeRequestId 发给新连接。
13. 过期/已结束卡片从待处理区移除或折叠到历史，提供关闭操作。展示关闭状态按稳定 ID 持久化，重启后不重新占据待处理区；关闭展示不删除审计事实。
14. 问题/凭据沿用类型化表单与当前保密行为；凭据值不写事件、普通 KV、日志或回执，凭据处理资源随请求结束释放。

### 7.4 请求界面与停用
